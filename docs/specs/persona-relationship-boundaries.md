# 페르소나의 정체성·관계의 경계·재선택

시작 관계의 현재 계약은 [시작 관계](starting-relationship.md)를 따른다. 연락받기 신청에서
연인(기본값)·썸·친구·낯선 사이를 선택하며, 연인은 막 사귀기 시작한 사이이다.

## 제품 계약

- 서비스 이름은 **Ren AI**다. 페르소나는 Ren AI와 ren.ai를 이 서비스의 언급으로 알아듣는다. 서비스에 대한 지식은 사용자의 프로필·이름·사진·취향을 안다는 뜻이 아니다.
- 평소에는 자기 성격과 말투로 이야기한다. AI인지 직접 물으면 사실대로 답하며 실제 인간·실제 신체·현실의 만남을 주장하거나 약속하지 않는다. 잘못된 말은 인정하고 정정한 내용을 유지한다.
- 다른 사람과도 대화하는지 직접 물으면 그렇다고 사실대로 답한다. 먼저 화제로 삼거나 비교·질투 소재로 쓰지 않으며 다른 사용자의 신원·사적 사실·대화 내용을 드러내지 않는다. 공유 State·Life memory와 사적인 Relationship 범위는 [ADR-0023](../adr/0023-personas-share-one-life-across-up-to-five-conversations.md)을 따른다.
- 초기 호감은 상대에 대한 긍정적인 마음과 관심이다. 시작 관계와 별개이며 이미 쌓인 신뢰·친숙함·공동 경험을 뜻하지 않는다. 연인 모드에는 고백이나 호감도 문턱이 필요 없고, 친구는 호감도 상승만으로 썸이 되지 않는다. 페르소나는 자기 취향과 경계를 유지하고 거절·불쾌함·수치심·분노를 표현할 수 있다.
- 제안 거절, 일시적인 대화 중단, 영구적인 관계 종료는 다르다. 실제 언행과 관계 맥락을 근거로 더 이상 교류하고 싶지 않으면 바로 종료할 수도 있다. 경고 횟수나 의무적인 재기회 절차는 없다. 취향·의견 차이만으로 상대를 문제 있는 사람으로 취급하지 않는다.
- 서율의 코스프레·서브컬처 게임·성수 팝업 취향과 밝은 적극성은 유지한다. 특정 작품을 해봤다는 경험, 사용자 프로필 열람, 쌓이지 않은 특별한 신뢰를 자동으로 만들어내지 않는다.

## 관계 종료

`end_conversation`은 현재 OpenCode 세션에 연결된 Conversation만 종료한다. 입력은 캐릭터 말투의 마지막 인사이며 수신자나 다른 Conversation ID를 받지 않는다. 제안 거절이나 휴식에는 사용하지 않는다.

애플리케이션은 종료 상태와 마지막 인사·서비스 안내 작업을 먼저 영속적으로 기록한다. 같은 호출이나 세션의 재요청은 새 종료를 만들지 않는다. 종료 후 일반 send/read/react/wait, 수신 실행, follow-up, 실패 실행 재시도와 재구축은 관계를 재개하지 않는다. 일반 발송과 종료 기록을 직렬화하고, 타이핑 중 종료된 Conversation의 발송도 저장 경계에서 차단한다.

종료는 서비스 전체의 blocked와 별개다. 이전 Conversation·세션·Relationship state·Relationship memory·발송 기록을 보존하며 handle당 현재 배정은 최대 하나다. 종료한 페르소나는 그 handle에만 영구히 재배정하지 않는다. 다른 Conversation과 공유 State·Life memory는 계속되며 다른 사용자에게는 공개·배정 가능하다. 전역 은퇴 상태는 없다.

관계 종료, OpenCode 정지, 마지막 인사 전달, 서비스 안내 전달은 독립적인 결과다. 종료 도구는 기록 후 반환하며 자기 세션의 중단을 기다리지 않는다. 별도 작업이 세션을 interrupt하고 inbox의 대기 입력을 취소한 뒤 실행 정지를 확인한다. 세션이 없어도 실행 불가능함을 확인한 것으로 처리하며, 서버 재시작 시 보존된 종료 관계의 정지를 다시 확인한다. 미완료 정지는 영속적인 공정 순서로 재시도한다.

마지막 인사와 `[Ren AI]` 재선택 안내는 Outbox로 전달하되 인사의 실패·불확실한 결과가 서비스 안내를 막지 않는다. 같은 메시지의 불확실한 발송을 맹목적으로 반복하지 않고 Messages의 관측 결과로 갱신한다. 인사·안내의 대기 여부와 재시도 번호를 별도로 보관한다. 사용자 전체가 차단·삭제 중이거나 이미 재선택했다면 이전 관계의 추가 안내를 보내지 않는다.

일반 수신·첫 연락·실패 복구가 종료 안내를 기다리지 않게 한다. 종료 전달은 heartbeat당 관계 한 건, 최대 3초로 제한하고 타이핑 연출을 사용하지 않는다. 세션 정지는 별도로 한 건·최대 5초이며 전달과 병행한다. 제한 시간에 중단된 외부 전송은 기록된 불확실한 작업으로 남아 관측 기반으로 이어간다.

## 다른 페르소나 재선택

서비스 안내는 `https://renai.im/#reselect=...` 비공개 링크를 기존 iMessage 주소로 보낸다. 토큰은 256비트 난수이며 서버 조회에는 해시를 사용한다. 브라우저는 fragment 토큰을 비공개 재선택 목록 조회와 등록 제출에 전달한다. 재선택 목록은 그 handle과 종료한 페르소나만 제외하고 일반 공개 목록은 유지한다. 로그·공개 프로필에는 토큰이나 종료 대사를 포함하지 않는다.

사용자는 Discovery에서 다른 후보를 Like하고 기존 주소·동의·Turnstile과 함께 제출한다. 서버는 최신 종료 기록의 토큰과 주소를 함께 검증하며 안내 발송 확인 여부로 재선택 권한을 막지 않는다. 일반 주소 입력만으로 기존 사용자를 재배정하지 않는다. 토큰은 한 번의 새 대기 등록에만 사용되며 응답 유실 뒤의 같은 등록 재시도는 중복 등록을 만들지 않는다. 더 새로운 Conversation이 있으면 이전 종료의 토큰으로 새 등록을 만들 수 없다. Discovery는 재선택 맥락·기존 주소 안내와 유효하지 않은 링크 오류를 일반 등록 오류와 구분한다.

재선택도 기존 운영자 Selection과 지연된 첫 Greeting을 사용한다. 즉시 배정을 약속하지 않는다. 새 Conversation은 해당 Persona의 현재 공유 State·Life memory와 새 Relationship 범위에서 시작하며 이전 관계의 비공개 기억·사용자 평가·대화 이력을 복사하지 않는다. 새 페르소나의 첫 발송에는 서비스가 다른 페르소나와의 새 대화임을 표시한다. 이전 페르소나의 지연된 발송 결과나 새 관계 시작 전 수신 대기 메시지는 새 페르소나의 대화로 전달하지 않는다.

Selection과 테스트 즉시 시작은 같은 예약 트랜잭션에서 handle당 하나·페르소나당 다섯 현재 배정을
검사한다. 대기·실패·불확실 첫 연락과 테스트 handle도 센다. 정원에 찬 페르소나도 Discovery에는
표시하며 정원 badge는 두지 않는다.

## 데이터와 운영

이번 스키마 변경은 사용자의 명시적인 데이터 보존 승인에 따라 마이그레이션을 제공한다. Conversation의 사용자별 UNIQUE를 활성 관계에만 적용하는 인덱스로 대체한다. 부모 재작성 중 자식 FK의 CASCADE/SET NULL이 실행되지 않도록 send·follow_up을 함께 보존하고, 같은 트랜잭션에서 원래 FK·제약과 데이터를 복원한다. 외래 키 검사 실패나 중간 실패는 전체 변경을 롤백한다.

Discovery 등록의 주소별 UNIQUE도 현재 등록에만 적용한다. 이전 등록은 archived_at으로 이력화하고 Like·선정·첫 연락·언어·동의를 보존한 채 새 등록을 만든다. User의 최초 가입·동의 정보는 유지하고 새 동의는 새 등록에 보존한다. 이전 첫 수신 시각은 Conversation.first_received_at에 보존하며 이후 수신도 관계별로 기록한다.

Admin은 기존 응답 상태를 계속 처리하며 선택적인 relationshipEnd 필드가 있으면 관계 종료와 안내 전달 여부를 표시한다. 비공개 종료 문구와 링크는 공개 응답에 포함하지 않는다.

## Admin 대화 상태

- `/conversations`: 활성 관계 기본 목록, 활성/종료/전체 필터, 사용자 주소·페르소나 ID·Session ID 검색과 25개 단위 커서 페이지 이동.
- `/conversations/:id`: 사용자–Persona–Conversation ID–OpenCode Session ID, 시작·종료·최근 수신/발송, 마지막 정지 확인, 실제 실행/유휴/세션 없음/조회 실패, inbox 개수와 예약 연락, 인사·안내 전달 결과, 같은 사용자의 관계·등록·선정 이력. 관계 이력은 최근 25개와 전체 검색 목록 링크를 제공하고 등록 이력도 25개 단위 커서로 이전 기록을 계속 조회한다.
- 목록과 연결 정보는 애플리케이션 DB에서 읽는다. 상세의 실행 상태는 OpenCode의 실제 active/get/inbox API로 조회하며 마지막 assistant outcome만으로 실행 여부를 추정하지 않는다. 조회는 intake·폴더 동기화·모델 재개를 시작하지 않는 별도 metadata 연결을 사용한다.
- 상세 새로고침은 기존 전송의 결과도 관측해 갱신한다. executor 조회 실패에도 DB 연결 정보를 표시하며 실패를 정지됨으로 표현하지 않는다.
- 운영자는 정지 재시도, 확정 실패한 인사 재시도, 재선택 링크 재안내를 요청할 수 있다. 결과 불확실 발송은 먼저 확인한다. 안내 재전달은 확인된 메시지도 새 시도로 보낼 수 있는 명시적인 운영자 행동이다. 재선택 완료 뒤에는 이전 안내를 재전달하지 않는다.
- 복구 요청 ID는 같은 관계·행동에 영속적으로 중복 제거한다. 다른 행동에 같은 ID를 쓰면 충돌로 거부한다. DB 상태만 큐에 기록하고 별도 작업이 실행한다. 기존 Basic 인증·서버간 Bearer 인증·동일 출처 폼 제출 검사를 유지한다.
- DB 조회는 `/management/conversations`와 `/management/conversations/:id?registrationsBefore=...`, 실행 조회·복구는 `/operator/conversations`를 사용한다. 등록 커서는 생성 시각과 ID를 함께 비교해 같은 시각의 기록도 누락·중복 없이 넘긴다. 모두 비공개·no-store이며 종료 대사·링크 토큰·Memory는 조회 응답이나 로그에 포함하지 않는다.

## 배포 절차

1. 실행을 일시 정지하고 기존 api-app 상태와 OpenCode 세션·폴더의 백업을 함께 확보한다. 이 작업은 운영 배포 시 수행한다.
2. 스키마 025/026과 새 API를 적용한다. 전환 전후 User·Conversation·send·follow_up·등록/Like/언어/선정/첫 연락 수와 원래 ID 연결을 비교하고 foreign_key_check를 확인한다.
3. 새 플러그인이 포함된 executor 아티팩트를 설치하고 실제 실행 revision·readiness를 확인한다. 아티팩트 발행만으로 설치 완료로 판단하지 않는다.
4. Admin·Discovery를 적용하고 비공개 대화 상태에서 기존 연결·실제 실행 상태를 확인한 뒤 실행을 재개한다. 테스트 handle로 종료·정지·재선택·새 첫 인사와 이전 기록 보존을 점검한다.
5. 실패 시 이전 아티팩트와 대응하는 DB·세션 백업을 함께 복원한다. 서로 다른 스키마 버전의 상태를 임의로 섞지 않는다. 본 개발 작업은 운영 DB 변경이나 배포를 자동으로 수행하지 않는다.

## 검증

- 실제 세션에 등록된 도구와 인증된 RPC를 통한 종료, 다른 세션·수신자 접근 차단.
- 종료 후 일반 행동 차단, 동시 발송·종료, 서버 재시작·상태 내보내기/복원, 불확실한 발송의 관측 기반 처리.
- 기존 사용자·Conversation·발송·예약 연락 보존과 마이그레이션 실패 롤백.
- 재선택 토큰의 주소 결합·일회 사용·중복 제출·이전 관계 토큰 무효화, 운영자 Selection과 새 Greeting.
- 이전 관계의 메시지·Memory 격리와 새 관계 안내, 한국어·영어·일본어 서비스 문구.
- 실제 종료 작업 경계에서 요청 ID·실패 단계·원인과 비공개 데이터 제외, Admin 종료 상태 표시.
- 실제 OpenCode의 장시간 wait·대기 입력 중단과 세션 보존, 읽기 전용 실행 상태 조회, 운영자 복구의 중복·충돌·불확실 전송 처리.
- Durable Object SQLite에서 이전 등록 스키마의 데이터·FK를 보존하는 변환, 서버 재시작 후 상태 유지.
- Admin 인증·검색·페이지 이동·상세·executor 장애 시 부분 표시·동일 출처 복구 요청, 재선택 UI와 오류 안내.

프롬프트의 자연스러움과 자발적인 종료 판단은 실제 모델로 별도 대화 평가한다. 스크립트 모델 테스트는 지침을 읽은 모델의 판단 품질을 증명하지 않으며 도구·데이터·실행 계약을 검증한다.
