# Ren AI 유저 초대장

## 운영 규칙

- Admin의 **대기자 관리 → 초대장 지급 ON/OFF**에서 신규 지급만 제어한다. 기본값은 OFF다.
- ON일 때 최초 선정되는 유저에게 일회용 초대장 2장을 지급한다. 운영자 선정과 초대 자동 선정에 같은 규칙을 적용한다.
- OFF여도 발급한 초대장은 만료·회수하지 않고 계속 사용할 수 있다. OFF일 때 초대받아 선정된 유저에게는 새 초대장을 지급하지 않는다.
- 다시 켜도 과거 선정자에게 소급 지급하지 않는다. 재선정·테스트 Reset·서버 교체로 초대장을 중복 지급하지 않는다.
- 자동 선정의 공개 모집 모드, 이벤트 기간·자동 종료, 기존 유저 일괄 지급은 이번 범위에 포함하지 않는다.

## 초대 흐름

1. 선정 트랜잭션에서 배정·첫 연락 예약과 초대장 2장·지급 영수증·발송할 Notification을 함께 저장한다.
2. Notification handle에서 유저에게 두 개의 공유 링크를 보낸다. 각 링크는 한 명에게만 사용할 수 있다.
3. 친구는 `/explore#invite=…`에서 페르소나를 고르고 기존 연락처·프로필·웹 동의·Turnstile 절차를 거친다. 토큰은 URL fragment에 두어 웹 서버·미리보기 요청에 전달하지 않는다.
4. 등록 후 기존 영속 Notification 작업에서 iMessage 사용 가능 여부를 확인한다. 사용 가능하고 공개 Like 후보에 배정 여유가 있으면 운영자의 별도 선정 없이 자동 선정한다.
5. 초대장 사용과 배정·첫 연락 예약·친구의 신규 초대장 지급을 같은 트랜잭션에서 확정한다. ON 상태라면 이 흐름이 다음 친구에게 이어진다.
6. 첫 연락은 기존 규칙대로 선정 후 5분~1시간 뒤에 예약한다. 초대는 선정 대기를 건너뛰는 것이며 즉시 메시지 전송을 뜻하지 않는다.

## 한도와 실패

- 본인 초대와 잘못된·다른 사람이 사용한 토큰은 거절한다. 링크 열람·공유·등록만으로는 초대장을 소진하지 않는다.
- 한 토큰의 여러 등록이 경쟁해도 한 사람만 사용할 수 있다. 실패한 사용은 배정과 신규 지급까지 롤백한다.
- 현재 페르소나당 5명 한도, 차단·삭제·관계 종료 이력과 iMessage 확인 조건을 유지한다. 배정 불가·iMessage 확인 실패 시 선정하지 않고 초대장도 소진하지 않는다. 기존 대기자 관리에서 원인을 확인할 수 있고, 등록을 재제출하면 미사용 초대장으로 다시 자동 선정을 시도한다.
- Notification은 기존 영속 큐·발송 한도·불확실한 결과의 자동 재발송 금지 규칙을 따른다. Admin의 유저 행에서도 발급한 링크와 사용 여부를 확인할 수 있다.
- 공개 응답·Persona·Conversation에 초대 토큰이나 지급 작업 상태를 추가하지 않는다. 운영자 인증이 필요한 대기자 목록에서만 링크를 조회한다. 로그에 토큰·연락처·Notification 본문을 남기지 않는다.

## 배포

API의 선택적 초대 입력·선택적 관리 응답 필드를 먼저 배포하고 Discovery와 Admin을 배포한다. API가 아직 예전 응답을 제공하면 Admin은 지급 설정을 표시하지 않고 기존 선정 기능을 유지한다. 배포 전에 선정된 Handle도 일회 지급 영수증으로 기록해 이후 재선정 시 소급 지급되지 않게 한다.
