# Ren AI 초대 코드

## 두 설정과 상속

각 초대 코드에는 두 숫자만 설정한다.

- **최대 사용 인원**: 해당 코드 하나로 선정할 수 있는 인원(1~10000).
- **초대장 지급 수**: 그 코드로 선정된 사람에게 새로 발급할 코드 개수(0~100).

선정자에게 지급하는 모든 새 코드는 부모의 두 설정을 그대로 상속한다. 사용
횟수는 각각 0에서 시작한다. 한도는 계통 전체 합계가 아니라 **코드마다 독립적**이다.
예를 들어 `THREAD20 / 최대 20명 / 지급 2개`로 선정된 A에게는 각각 최대 20명·지급
2개인 고유 코드 2개가 발급된다. 다음 세대에도 같은 규칙을 적용한다. 지급 수가
0이면 후속 코드를 발급하지 않는다. 최초 유입과 후속 유입 설정은 분리하지 않는다.

## 운영자 발급

- Admin의 대기자 관리에서 **연락처 없이 초대 코드 만들기**를 제공한다. 공통 모집
  코드는 `THREAD20`처럼 직접 정하고, 비워 두면 무작위 고유 코드를 생성한다.
  직접 입력은 영문·숫자·밑줄·하이픈 1~64자이며, 대소문자는 구분하지 않는다.
- 발급한 코드와 공유 링크, 사용 인원/한도, 지급 수를 최근 50개까지 표시한다.
  운영자는 이를 복사해 Threads 공개 게시·DM·이메일로 전달한다. 수신자 연락처,
  User 또는 대기 등록 생성이나 자동 메시지 발송은 필요하지 않다.
- 전화번호 수동 지급도 유지한다. 미등록 번호에도 기본 2장을 한 번 지급하거나
  요청마다 1장을 추가할 수 있다. 각 지급 코드의 최대 사용 인원과 후속 지급 수를
  지정하며 기본값은 1명·2개다. 지급 대상 번호는 전달·지급 이력 기준이며 본인이나
  다른 사람이 사용할 수 있다.
- 수동 코드 생성과 번호 지급은 요청 ID로 중복을 방지한다. 결과가 불확실하면
  같은 입력과 요청 ID로 확인한다. 새 요청으로 이미 존재하는 코드를 만들거나,
  같은 요청의 대상·설정·언어를 바꾸면 충돌로 거절한다.

## 자동 지급

- **초대장 지급 ON/OFF**는 자동 신규 지급만 제어하며 기본값은 OFF다. 수동 발급은
  OFF여도 가능하다. 발급한 코드 사용도 스위치와 무관하다.
- ON 상태에서 최초 선정된 Handle에게 한 번 지급한다. 초대 코드로 선정됐다면
  부모 설정을 상속하고 지급 수만큼 발급한다. 코드 없는 운영자 선정은 기본값
  (각 코드 최대 1명·지급 2개)으로 2개를 발급한다.
- OFF 상태에서 선정된 사람에게 나중에 소급 지급하지 않는다. 재선정·테스트
  Reset·재시도·서버 교체로 중복 지급하지 않는다. 이미 수동 기본 지급을 받았다면
  자동 기본 지급을 반복하지 않으며, 추가 지급만 받은 경우에는 최초 자동 지급이 가능하다.

## 초대 사용 흐름

1. `/explore#invite=…` 링크는 연락받기 화면의 코드를 자동으로 입력한다. 직접
   방문한 사람도 선택 입력란에 코드를 넣을 수 있고, 코드 없이 대기 등록할 수 있다.
   코드는 URL fragment에 두어 웹 서버·미리보기 요청에 전달하지 않는다.
2. 기존 연락처·프로필·웹 동의·Turnstile 절차를 거친다. 링크 열람·공유·대기 등록만으로는
   사용 인원을 차감하지 않는다.
3. 기존 영속 Notification 작업에서 iMessage 사용 가능 여부를 확인한다. 사용 가능하고
   공개 Like 후보에 배정 여유가 있으면 별도 운영자 선정 없이 자동 선정한다.
4. 사용 횟수 증가·Handle별 사용 영수증·배정·첫 연락 예약·후속 코드 지급을 같은
   트랜잭션에서 확정한다. 마지막 자리에 여러 사람이 경쟁해도 한도를 넘지 않으며,
   실패한 선정은 배정과 지급까지 롤백한다. 재시도는 다시 차감하거나 지급하지 않는다.
5. 첫 연락은 선정 후 5분~1시간 뒤에 예약한다. 초대는 선정 대기를 건너뛰는 것이며
   즉시 메시지 전송을 뜻하지 않는다.

## 실패·복구·공개 경계

- 잘못된 코드와 사용 한도를 채운 코드는 거절한다. 본인 사용은 허용한다.
- 페르소나당 현재 배정 5명, 차단·삭제·관계 종료 이력과 iMessage 확인 조건을 유지한다.
  배정 불가·iMessage 확인 실패 시 코드를 소진하지 않는다. 대기자 관리에서 원인을
  확인할 수 있으며 동의한 신청을 재제출하면 다시 시도한다.
- Notification은 기존 영속 큐·시간당 30회 발송 한도·불확실한 전송의 자동 재발송 금지
  규칙을 따른다. 발송 실패여도 저장된 링크는 유효하다. 완료된 선정 안내의 영수증도
  서버 교체 후 보존한다.
- 공개 응답·Persona·Conversation에 코드·지급 작업 상태를 추가하지 않는다. 운영자
  인증 경계 안에서만 발급 이력을 조회한다. 코드·연락처·Notification 본문은 로그에 남기지 않는다.

## 배포

이 기능의 미병합 초대 스키마를 함께 배포한다. API의 선택적 초대 입력과 선택적
관리 응답 필드를 먼저 배포하고 Discovery와 Admin을 배포한다. 사용 횟수·한도·지급 수가
없는 이전 API 응답도 클라이언트가 처리한다. 기능 배포 전 선정된 Handle은 최초 지급
영수증으로 기록해 재선정 시 소급 지급되지 않게 한다.
