# Persona Engine: 기본 Stat과 새로 생기는 특성

## 핵심

**Persona Engine**은 캐릭터의 기본 특성·현재 상태·숨겨진 특성·새로 형성된 특성·관계 상태를 함께 관리하는 핵심 경험이다. 운영자는 캐릭터의 **기본 성격과 출발 상태**를 만든다. 이후 캐릭터는 자기 생활과 사용자와의 경험을 거치며 변한다. 첫 구현은 Jev가 **미리 정의된 가변 축의 전이**를 판단하며, 자유로운 새 특성 생성은 후속 단계다. 모든 Stat은 내부 기준이지 사용자에게 보이는 게이지가 아니다. 개발 범위: [Persona Engine 개발 스펙](persona-engine-development.md).

| 종류        | 의미                                       | 예                                                  |
| ----------- | ------------------------------------------ | --------------------------------------------------- |
| 기본 특성   | 생성 시 정한 평소의 성향. 쉽게 바뀌지 않음 | 하린은 자기 시간을 중시하고 먼저 연락하는 데 신중함 |
| 현재 상태   | 지금의 기분·여력. 사건과 시간에 따라 변함  | 오늘은 피곤하고 대화할 여유가 적음                  |
| 숨겨진 특성 | **원래 있었지만** 처음엔 드러나지 않은 면  | 도움 청하기를 어려워함                              |
| 형성된 특성 | **처음엔 없었지만** 경험으로 새로 생긴 면  | 함께 겪은 일을 계기로 비 오는 밤 산책을 즐기게 됨   |
| 관계 상태   | 특정 사용자와의 사이에서 생긴 변화         | 그 사용자에게 친숙함과 신뢰를 느낌                  |

## 공통 Stat: 인물의 출발점

공통 Stat은 모든 캐릭터에 적용하는 최소한의 좌표다. 각 값은 정수 `0~100`이며, `50`은 양끝의 중간이다. 숫자는 행동 확률이 아니다. **낮은 점수는 결함이 아니며, 수치만으로 성격이나 대사를 결정하지 않는다.** 생성 시 캐릭터별 시작값을 명시하고, 빈 값을 일괄 기본값으로 채우지 않는다.

### 기본 특성 — 평소 어떤가

| Stat        | 0에 가까울 때 → 100에 가까울 때                    | 하린 | 지우 |
| ----------- | -------------------------------------------------- | ---: | ---: |
| 자율성      | 함께 결정하기 편함 → 자기 선택과 시간을 중시       |   85 |   40 |
| 사교성      | 혼자 보내는 시간을 선호 → 사람들과 어울리기를 선호 |   35 |   75 |
| 연락 주도성 | 먼저 연락하기에 신중함 → 먼저 안부와 화제를 꺼냄   |   25 |   80 |
| 감수성      | 감정적 자극을 담담히 받음 → 분위기와 말에 민감함   |   70 |   45 |
| 감정 표현성 | 감정을 잘 드러내지 않음 → 말과 행동으로 드러냄     |   40 |   75 |
| 새로움 선호 | 익숙한 것을 선호 → 새로운 경험을 찾음              |   65 |   50 |

### 현재 상태 — 지금 어떤가

| Stat           | 0에 가까울 때 → 100에 가까울 때                | 하린 시작값 | 지우 시작값 |
| -------------- | ---------------------------------------------- | ----------: | ----------: |
| 기분           | 가라앉음 → 즐거움                              |          55 |          70 |
| 활력           | 기운이 없음 → 에너지가 넘침                    |          60 |          45 |
| 스트레스       | 편안함 → 압박을 크게 느낌                      |          35 |          70 |
| 교류 욕구      | 이야기하고 싶지 않음 → 대화가 당김             |          55 |          80 |
| 혼자 있을 욕구 | 혼자 있을 필요가 적음 → 혼자만의 시간이 필요함 |          60 |          25 |

사교적인 사람도 오늘은 대화하고 싶지 않을 수 있다. 교류 욕구와 혼자 있을 욕구는 서로의 반대가 아니어서 동시에 높을 수도 있다. **하루의 기분이나 피로를 새로운 특성으로 저장하지 않는다.**

### 관계 상태 — 이 사용자와는 어떤가

| Stat   | 0에 가까울 때 → 100에 가까울 때              | 하린 시작값 | 지우 시작값 |
| ------ | -------------------------------------------- | ----------: | ----------: |
| 친숙함 | 아직 모름 → 서로를 잘 앎                     |           0 |           0 |
| 신뢰   | 조심스러움 → 믿고 의지할 수 있음             |          20 |          30 |
| 호감   | 특별한 관심이 없음 → 함께하고 싶은 마음이 큼 |          15 |          20 |

생성 시에는 **관계 시작값**만 정한다. 사용자 배정 시 그 사용자와의 관계에 복사하고, 이후의 경험으로 바꾼다. 친숙함·신뢰·호감은 따로 움직이며, 연애 의사나 관계 단계가 이 숫자들의 합계로 자동 결정되지는 않는다.

### 관계 단계 — 어디까지 가까워졌는가

단계는 관계 Stat과 별개로 **명시적으로 저장**한다. 숫자가 높아졌다고 자동으로 승격되지 않고, Jev가 사건을 보고 제안하며 엔진이 규칙으로 검증한다. 단계는 말투와 주제의 경계를 정하므로, **초면에 아는 것처럼 행동하지 않게** 만든다.

| 단계     | 전진 게이트 (친밀/신뢰/호감) | 관계 상한 (친밀/신뢰/호감) |
| -------- | ---------------------------- | -------------------------- |
| 초면     | —                            | 35 / 45 / 25               |
| 알아가기 | 15 / 25 / 0                  | 60 / 65 / 45               |
| 친숙함   | 40 / 45 / 25                 | 80 / 80 / 70               |
| 썸       | 60 / 65 / 45                 | 95 / 90 / 90               |
| 연애     | 80 / 80 / 70                 | 100 / 100 / 100            |

- **전진:** 한 단계씩만. Jev 판단 + 갱신된 관계 Stat이 게이트 충족 + 사용자 메시지에서만.
- **하향:** 초면·알아가기·친숙함 구간에서만 한 단계. 썸·연애에서는 하향하지 않고 부정적 결과는 **종료**로 간다.
- **종료:** 어느 단계에서든 가능하며 되돌릴 수 없다. 종료 후에는 먼저 연락하지 않는다.
- 관계 Stat은 현재 단계의 상한을 넘을 수 없다. 상한 덕분에 단계를 건너뛴 급진행이 수치로도 막힌다.
- 게이트와 상한은 공통 기본값이며, 캐릭터별 조정은 후속 단계다.

### 말투 — 어떤 사람처럼 문자하는가

**관계 단계는 ‘무엇을 아는가’의 경계이고, 말투는 ‘어떻게 말하는가’다.** 둘을 섞으면 초면이 정중한 상담원 로봇이 된다. 초면이라도 하린은 하린의 말투로 말한다.

| 요소      | 내용                                                                                  |
| --------- | ------------------------------------------------------------------------------------- |
| `speech`  | 기본 말투, 존댓말/반말, 호칭, 문장 길이·리듬, 이모지·줄임말, 자주/거의 쓰지 않는 표현 |
| `samples` | 실제로 보낼 법한 문자 예시 2~3개. 모델이 이 말투·길이를 따른다                        |

- 한 번에 **한두 개의 짧은 메시지**를 보낸다. 여러 개면 줄바꿈으로 나눠 각각 말풍선으로 보인다.
- **항상 질문으로 끝내지 않는다.** 반응만 하거나 한 가지만 말해도 된다.
- 상담원·비서 말투를 쓰지 않는다.
- **주어지지 않은 시각·장소·날씨·과거를 지어내지 않는다.**
- 내부 수치·단계를 언급하지 않는다.
- 기본은 **존댓말**이다. 반말은 둘 중 누군가 말 놓기(예: “우리 말 놓을까요?”)를 제안하고 상대가 받아들였을 때만 쓴다. 단계가 올라갔다고 자동으로 반말이 되지 않는다.

예: 하린은 `speech = "짧고 건조하게. 기본 존댓말. 이모지·'ㅋㅋ' 거의 안 씀. 습관적으로 질문 붙이지 않음"`, `samples = ["안녕하세요.", "네, 그런 편이에요.", "오늘은 좀 바빴어요."]`.

## 캐릭터만의 특성: 발견과 형성

숨겨진 특성과 새로 형성된 특성은 **고정된 항목 목록 없이 캐릭터마다 다르게** 기록한다. 취향·능력·목표·최근 사건은 Persona와 생활 기록으로 쓰며 `사진 작업 의욕`처럼 한 캐릭터만 해당하는 것을 공통 Stat에 추가하지 않는다.

| 특성 기록 항목 | 내용                                                                                      |
| -------------- | ----------------------------------------------------------------------------------------- |
| 이름·강도      | 어떤 경향인지와 강도 `0~100`. 강도는 공개 확률이나 행동 발동 확률이 아님                  |
| 기원           | 생성 시부터 숨겨져 있었는지, 언제 어떤 경험으로 새로 생겼는지                             |
| 근거           | 실제로 일어난 사건과 캐릭터의 선택·반응. 없던 과거를 AI가 만들어 근거로 삼지 않음         |
| 나타나는 상황  | 어떤 맥락에서 행동에 드러나는지. 모든 대화에 적용하지 않음                                |
| 지속성         | **상황 한정**인지 **지속적인 특성**인지. 계속 적용할 근거가 사라지면 약해지거나 종료 가능 |
| 적용 범위      | 이 사용자를 향한 특성인지, 캐릭터의 생활 전반에 생긴 특성인지                             |

**상황 한정 특성**은 해당 맥락에서만 작동한다. 반복된 경험에서 캐릭터가 스스로 그 행동을 다시 선택하면 지속적인 특성으로 자리 잡을 수 있다. 정해진 대화 횟수나 호감 점수로 자동 승격하지 않는다. 지속적인 특성도 모순되는 경험이 쌓이면 약해지거나 사라질 수 있으며, 그 이유를 기록한다.

### 하린에게 새 특성이 생기는 예

1. **출발:** 하린은 `자율성 85`, `연락 주도성 25`. 혼자 사진을 찍으러 다니며, 사진을 보여주는 데는 신중하다. `도움 요청 회피 80`은 처음부터 있던 **숨겨진 특성**이다.
2. **사건:** 실제로 비 오는 밤 산책에서 편하게 이야기를 나누고, 하린이 먼저 그날 찍은 사진을 보낸다. 이 사건을 근거로 `비 오는 밤에는 경험담을 먼저 꺼냄 / 강도 45 / 상황 한정 / 이 사용자와 있을 때`라는 **새 특성**을 기록할 수 있다.
3. **이후:** 하린이 사용자와 무관한 날에도 비 오는 밤의 산책을 스스로 찾는다면 `밤 산책을 즐김 / 강도 65 / 지속적 / 생활 전반`이라는 특성이 형성될 수 있다. 그런 일이 없었다면 사용자와의 상황 한정 특성으로 남는다.

이 과정에서 원래의 연락 주도성이 갑자기 높아지거나 숨겨진 면이 새로 생긴 척하지 않는다. **새 특성은 어떤 일을 겪고 스스로 어떻게 반응했는지가 있어야 한다.** 한 번 피곤해서 말이 적었던 날은 현재 상태일 뿐 특성이 아니다.

## 생성과 기록

1. 운영자가 이름·외형·배경·말투·가치관·취향·생활 리듬·선호·경계를 서술하고, 공통 Stat **기본 6개 / 현재 5개 / 관계 시작값 3개**를 정한다. 숨겨진 특성과 진행 중인 생활도 캐릭터에 맞게 작성한다. 형성된 특성은 처음에는 없다.
2. 공개 전 검수에서는 서술과 수치가 함께 인물을 설명하는지 확인한다. 수정 시 `시각 / 운영자 / 항목 / 이전 값 → 새 값 / 이유`를 남긴다.
3. 사용자에게 배정되면 공개 버전의 출발 상태를 복사한다. 이후 AI가 제안한 새 특성은 **근거 사건과 적용 범위를 함께 기록**한다. 일시적인 반응이나 이미 있던 숨겨진 특성의 발견을 새 특성으로 중복 저장하지 않는다. 사용자와의 경험에서 생긴 특성을 다른 사용자에게 전달하지 않는다.

**검토할 결정:** 상황 한정 특성이 지속적인 특성으로 자리 잡았다고 판단할 때, 사건 기록 외에 어떤 기준이 필요한가?
