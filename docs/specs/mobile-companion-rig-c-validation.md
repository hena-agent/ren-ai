# RenAI rig-c 검증 기록

## 2026-11-12: 잘린 홍채 이동·눈꺼풀 침범 수정

- 사용자가 시선을 움직인 확대 화면에서 수평으로 잘린 홍채가 드러나는 결함을 지적했다. 이전 구현은 눈꺼풀에 가려진 모양을 홍채 알파에 굽혀 넣고, 마스크 없이 모든 눈동자를 고정 ±2 rig 단위로 이동했다. 정면 표정·일반 고개 화면 확인만으로 시선 기능을 완료로 보고한 검수가 부족했다.
- 실제 저장된 눈/홍채 PNG를 읽는 검사에서 중앙은 침범 0이었지만 상향 이동은 좌/우 42/40개, 하향 이동은 26/20개의 불투명 홍채 픽셀이 흰자 영역을 벗어났다. 실제 모델 구성 경로를 호출하는 `rig-face-gaze.test.ts`를 먼저 실행해 눈 마스크 slot이 없다는 실패를 확인했다.
- 기존 놀람 원본의 홍채에서 완전한 원형 알파·상단 곡선을 복원했다. 눈꺼풀 뒤의 숨은 부분과 흰자 색이 섞인 테두리를 보정하고, 고정된 흰자·눈 안쪽 마스크·움직이는 홍채·눈꺼풀 덮개를 분리했다. 부품은 19개에서 23개가 됐으며 기존 몸·머리카락 17개와 관절·얼굴 실루엣·목 보정 픽셀은 유지했다. 추가 유료 호출은 0회다.
- 재생기는 rig-c의 네이티브 clipping attachment를 사용한다. 원본 좌표 `aperture`의 가중치는 head에만 두고 종료 slot을 해당 홍채 하나로 한정했다. 표시 필터도 활성 홍채의 비시각적 clip slot을 유지한다. 눈감기에서는 홍채·clip·열린 눈꺼풀 덮개를 함께 숨긴다. 이동량은 각 눈·표정의 `gaze` 픽셀 범위를 rig 단위로 변환하고 범위를 제한한다. 마스크 없이 잘린 홍채를 이동하는 경로는 제거했다.
- 평상·놀람 각각 상하좌우·중앙·대각선의 **18개 실제 Canvas 캡처**를 비교한다. 몸을 정지시키고 스크롤을 고정한 채 입력 이벤트를 전달해 안티앨리어싱의 스크롤 오차를 분리했다. `gaze-audit.py`는 홍채 알파의 원형·상하좌우 대칭과 고정 눈 경계 밖 화면 변화가 없는지 검사한다. 경계에는 2px 래스터 여유를 두며 이 영역 밖 변화는 18개 모두 0이다. `.playwright-mcp/gaze-fixed-{neutral,surprised}-grid.png`가 9방향 비교다.
- 좌우 고개 고정에서 평상·놀람의 중앙·대각선을 추가로 캡처해 총 **38개 프레임**에서 회전한 눈 경계 밖 변화 0을 확인했다. 눈감기에서는 홍채와 열린 눈꺼풀 덮개가 보이지 않는 것도 실제 화면으로 확인했다. 원본·부품 백업은 비공개 `face-generation/gaze-before/`, 현재 부품·픽셀 보존 검사는 `parts-applied.json`·`audit.json`, 화면 검사는 `gaze-audit.json`에 보관한다. 이 수정은 클로이의 해당 부품 검증이며 실제 휴대폰·전체 CI·운영 배포는 별도다.
- 관련 회귀 41개와 변경된 얼굴·클리핑·모델 실행 코드 6개 파일의 문장·분기·함수·줄 커버리지 각각 100%를 통과했다. 타입·미사용 코드·중복 검사·Admin 빌드도 통과했다.

## 2026-11-11~12: 실제 얼굴·표정 3장 생성과 19개 부품 적용

- 사용자의 명시적 생성 승인 후 Seedream 5 Flash Edit(`fal:bytedance/seedream/v5/flash/edit`)로 **얼굴 바탕 1장 / 감긴 눈·미소 1장 / 놀란 눈·벌린 입 1장**을 생성했다. 조회 단가는 US$0.027/장, 세 장의 표시 단가 합계는 **US$0.081**이다. 공급자 최종 청구액은 별도로 대조하지 않았다. 이번 작업의 유료 호출은 이 3회이며 Layerize·전신 재생성·유료 재시도는 없다.
- 얼굴 생성 경로를 기존 모델·단가 확인과 전역 Durable Object FIFO에 연결했다. 같은 몸의 원본에서 얼굴 주변을 잘라 1024×1536 참조로 확대하고 표정별로 독립 편집한다. 결과를 비공개 레이어 manifest의 `faceSources`에 모델·좌표·생성 영수증과 함께 보관하고 기존 몸·의상·머리카락은 교체하지 않는다. UI는 선택 프롬프트가 있는 한 장 확인을 유지한다.
- 완료 작업은 바탕 `/image-jobs/6c0dc3be-ae60-4a55-8931-6649dc3d03ec`, 감긴 눈·미소 `/image-jobs/daab91af-10b5-45d7-a8a6-f79832463554`, 놀람 `/image-jobs/557c9e01-5af4-4da7-861c-ca989e6311e4`다. 첫 결과 수집 스크립트가 레이어 검수용 내보내기에 얼굴 이력이 없다는 이유로 중단됐으나, 생성은 이미 성공·영속 저장되어 있었다. 편집 초안에서 기존 결과를 회수했으며 다시 생성하지 않았다.
- 원본 기준 전역 정합 점수는 0.9946~0.9985였지만 감긴 표정의 코·입 위치가 약 12~13px 내려간 차이가 남았다. 코와 미간의 불변 지점을 추가로 맞춰 부품을 추출했다. 첫 합성에서 피부색 패치·코 중복·눈썹 영역에 섞인 눈화장과 눈동자 경계가 드러나 재보정했다. 전역 정합 점수나 PNG 개수만으로 합격 판정하지 않았다.
- 평상 바탕·좌우 눈·좌우 눈동자·좌우 눈썹·입 8개에 양쪽 감긴 눈, 미소 입, 놀란 눈·눈동자·눈썹·입과 독립 벌린 입을 더해 **19개 PNG**를 로컬 R2/D1에 적용했다. 기존 얼굴의 실제 픽셀을 활용하고 생성 바탕으로 지워진 부위를 복원했다. 눈동자는 표정별 부품을 사용하고 눈감기에서는 숨긴다. 이는 현재 클로이에 맞춘 정합·매팅 작업이며 다른 페르소나의 무인 자동 제작 성공을 뜻하지 않는다.
- 빈 투명 영역을 잘라 원본 `bounds`로 배치했다. 얼굴 텍스처 합계는 **43,250,688 → 91,548픽셀**로 줄었다. 이는 텍스처 크기이며 휴대폰의 실제 메모리·프레임률 측정을 대신하지 않는다. 독립 비교로 기존 몸·머리카락 17개 레이어와 관절 좌표, 얼굴 실루엣 알파, 목의 원래 보정 픽셀이 유지됨을 확인했다.
- 실제 rig-c에서 평상·미소·눈감기·놀람·벌린 입·고개 기울임과 시선 이동을 확인했다. 정지 몸 모션에 자동 눈깜빡임을 켜 24개 캡처에서 뜬 눈/감긴 눈의 두 프레임을 확인했고 Canvas 1개·브라우저 오류 0개였다. `.playwright-mcp/face-generated-{neutral,happy-closed,surprised,head-gaze}.png`와 `face-generated-comparison.png`는 실제 재생 기록이다.
- 생각 중·걱정·반쯤 감긴 눈은 아직 별도 그림이 없으며 UI에서 비활성화한다. 현재 결과는 로컬 첫 표정 세트 검증이고 전체 CI·실제 휴대폰·운영 배포는 별도다. 비공개 참조·생성 원본·정합·부품·검사 기록은 임시 작업 공간의 `layerize-quality/face-generation/`에 보관했다.
- 집중 회귀 93개와 얼굴 실행 코드·공통 원화 배치 필드 파일의 문장·분기·함수·줄 커버리지 각각 100%를 확인했다. 포맷·린트·타입·미사용 코드·중복 검사·Admin 빌드도 통과했다. 기존 큐와 동일한 복구 경로를 사용하며 수작업 부품 적용은 별도로 source/result CAS를 확인했다.

## 2026-11-11: 공통 체형 가정·몸 기준 머리카락·얼굴 부품 검수

- 3D 도구 검토에서 2D로 복귀했다. 현재 보정된 몸·손·관절을 공통 체형으로 사용한다고 가정하고 얼굴·표정에 집중한다. 현재는 해당 페르소나의 몸을 재사용하는 단계이며 여러 페르소나가 참조하는 글로벌 몸 카탈로그를 구현한 것은 아니다.
- 머리카락의 앞·뒤는 시점이 아니라 몸·의상과의 가림 관계다. 레이어에 합성 영역을 저장하고 몸 뒤 머리카락 → 몸 → 의상 → 얼굴 → 몸 앞 머리카락 → 얼굴 위 앞머리 순으로 함께 합성한다. 기존의 몸 다음에 의상 전체를 붙이던 순서를 교체했다. 클로이의 Back Hair는 `behind-body`, Front Hair는 `front-body`로 로컬 D1에 저장했다. 기존 PNG·원화·관절·유료 생성 영수증은 보존했다.
- 얼굴 부품의 비공개 등록·교체·삭제와 CAS 저장, 얼굴 확대, 표정·눈감기·시선·입 제어를 추가했다. 평상 바탕·좌우 눈·좌우 눈동자·좌우 눈썹·입의 8장이 모두 있어야 기존 얼굴·목을 교체한다. 눈동자는 head 하위 관절에 연결하고 감긴 눈에서는 숨긴다. 얼굴 제어는 몸 모션을 재시작하거나 유료 API를 호출하지 않는다.
- **클로이의 실제 얼굴 부품은 아직 0장이다.** 원래 얼굴에는 눈·입이 그려져 있어 피부 바탕 복원과 눈/눈동자/눈썹/입 분리가 필요하다. 감긴 눈·추가 감정·입 안쪽은 원본에 없으므로 별도 제작이 필요하다. 해당 그림이 없는 상태에서 표정 제어를 활성화하거나 완성됐다고 표시하지 않는다.
- Chromium에서 기존 17개 PNG·한 개 Canvas의 재생, 저장 후 몸 앞·뒤 역할 유지, 얼굴 확대와 원래/기울인 고개를 확인했다. `.playwright-mcp/rig-face-body-planes-rest.png`, `rig-face-body-planes-left.png`는 기존 그림의 재생 기록이며 새 표정의 미술 품질 합격 자료가 아니다.
- 별도 브라우저 탭의 응답만 임시 대체해 단색 도형으로 된 평상 8부품·양쪽 감긴 눈을 실제 rig-c에서 재생했다. 원래 얼굴의 제거, 부품 합성·눈감기·시선 제어에서 페이지 오류 0개·Canvas 1개를 확인했다. `.playwright-mcp/rig-face-synthetic-closed.png`는 **기술 검증용 도형**이며 클로이 이미지로 저장하지 않았다. 테스트 탭은 닫았고 실제 저장 상태는 얼굴 0장·표정 제어 비활성화다.
- 추가 이미지 생성·Layerize 유료 호출은 0회다. 후속은 실제 얼굴 부품 제작과 표정별 시각 검수이며, 기술 검증을 실제 그림 완성으로 대체하지 않는다.
- 집중 회귀 52개를 통과했다. 새 얼굴 실행 코드 4개 파일과 공통 원화 요청 경계 파일의 문장·분기·함수·줄 커버리지는 각각 100%다. 전체 포맷·린트·타입·미사용 코드·중복 검사와 Admin 빌드도 통과했다. 전체 CI·GitHub Actions·운영 배포는 실행하지 않았다.

## 2026-11-11: 목·어깨 확대 재검수와 매팅/바탕 수정

- 사용자의 확대 화면에서 이전 완료 판정이 잘못됐음을 확인했다. 불완전한 머리카락 분류 마스크를 생성과 검사에 함께 써 잔여 선·피부색 조각을 누락했고, 이진 알파에 원본의 피부색 혼합 픽셀을 그대로 넣었다. 전신 축소 화면과 원래 자세 재합성만으로 움직이는 경계 품질을 판정하지 않는다.
- 기존 17개 결과를 비공개 `layerize-quality/underwear-before-matte/`에 보관했다. 별도 `hair-matte.py`로 아래쪽 머리카락의 전경색·연속 알파를 분리하고, 피부 바탕과 속옷 끈을 다시 복원했다. 명확히 보이는 중앙 목·쇄골의 원본 음영은 보존하고 가려졌던 짧은 부분만 연결했다. 끈 경계는 서브픽셀 곡선으로 그려 잘린 선과 계단 모양을 줄였다. 뒷머리에는 원본 어깨/피부 혼합 테두리 대신 머리카락 내부 색상을 사용했다.
- 생성 마스크와 별도로 지정한 피부 검수 영역, 원본 머리카락 위치 22곳, 실제 PNG 경계색과 소수 좌표의 알파 합성을 검사했다. 이전 결과에서 피부 영역 어두운 조각 6픽셀, 머리카락 경계의 피부색 805픽셀, 피부 급격한 단차 244픽셀, 턱 주변 알파 이음 382픽셀이 검출됐다. 최종 보정본은 네 값 모두 0이며 지정한 머리카락 위치도 모두 유지했다. 이 기준은 현재 그림의 결함을 잡는 회귀 기준이며 모든 미술적 품질을 자동 합격 처리하는 기준은 아니다.

## 브라우저에서 확인한 동작

공식 재생기 외에 임시 `welcome.html`을 만들어 앱 이벤트에 가까운 동작을 확인했다. 제품 UI가 아니라 상태를 드러내는 검증 화면이다.

- 로드 후 idle 위에 hello를 한 번 재생한다.
- hello가 끝나면 해당 트랙을 비우고 idle만 남긴다.
- 버튼 또는 화면 터치로 같은 hello를 다시 실행한다.
- 일시정지와 재생을 제공한다.
- 문서가 숨겨진 동안 프레임 진행을 멈추도록 구현했다. 실제 기기의 백그라운드 전환은 아직 검증하지 않았다.
- 상태와 호출 횟수를 표시한다.

별도의 터치 애니메이션은 만들지 않았다. 현재 터치는 환영 모션을 호출하는 입력일 뿐이다. 대화·기억·OpenCode 연결·음성도 없다.

확인한 API 조합:

```js
player.play("idle");
player.play("hello", { track: 1, loop: false, mix: 0.2 });
player.queueClear(1, { mix: 0.3 });
```

Playwright에서 다음을 확인했다.

- `hello` 트랙은 `loop: false`, 길이 4.75초로 시작했다.
- 5.3초 후 hello 트랙은 `null`, idle 트랙은 반복 재생 중이었다.
- 검증 화면의 버튼 재호출, idle 복귀, 일시정지·재생, 화면 터치 재호출이 동작했다.
- 390 × 844 화면에서 가로 넘침이 없었다.
- 공식 화면에서는 `favicon.ico` 404 한 건만 관찰했다. 모델·텍스처 로드 오류는 없었다.

### 제한된 실행 수치

공식 재생 화면에서 데스크톱 Chromium의 화면 크기를 390 × 844, DPR 1로 설정하고 측정했다. 이는 실제 스마트폰·모바일 Safari 측정이 아니다.

| 항목                 | 관찰값               |
| -------------------- | -------------------- |
| 프레임 간격 표본     | 초기 표본 제외 179개 |
| 중앙 프레임 간격     | 약 16.7ms            |
| p95 프레임 간격      | 약 17.5ms            |
| 모델 JSON 응답 본문  | 585,906 bytes        |
| 텍스처 PNG 응답 본문 | 618,925 bytes        |

프레임 간격은 `requestAnimationFrame` 간격이며 렌더 함수의 CPU 시간이나 GPU 부하가 아니다. 로컬 서버 수치로 네트워크 로딩 성능을 추정하지 않는다. 재생기 JS와 메모리·배터리·발열은 별도 측정이 필요하다. 목표 기기와 허용 기준을 사전에 정하지 않았으므로 성능 합격으로 판정하지 않는다.

## 비용과 에셋 조건

- 도구 설치와 로컬 빌드·재생만 수행했다. 유료 생성 API 비용은 없다.
- 제공된 원화·레이어를 사용했으므로 새 페르소나의 총 생성 비용·성공률은 아직 모른다.
- 예제 원화와 레이어는 CC BY-NC 4.0이다. 로컬 검증에 사용했으며 제품용 에셋으로 채택하지 않는다.
- 예제 NOTICE의 원화 출처: “Painted with Nova Anime XL IL v8.0 by Crody (https://civitai.com/models/376130).”
- rig-c 도구의 MIT 조건과 원화·외부 모델의 조건은 별개다.

## 다음 작업

1. **자체 원화 입력 확정:** 첫 페르소나의 그림체·구도와 원화, 레이어 분리 실행 경로를 정한다. 유료 이미지 생성은 이미지 옵션과 개별 프롬프트 확인 후 진행한다.
2. **자체 원화 전체 흐름:** 생성·분리부터 리깅까지 수행하고 비용·재시도·수작업 시간을 기록한다.
3. **표정 검증:** 실제 얼굴 표시 크기에서 알아보기·반가움·듣기의 차이가 전달되는지 판단한다. hello를 재생할 수 있다는 사실만으로 완료하지 않는다.
4. **실제 휴대폰:** 대상 기기와 기준을 먼저 정하고 모바일 브라우저에서 측정한다. 앱 방식 결정 후 WebView도 확인한다.
5. **비인간형:** 인간형 결과 이후 고양이 또는 공룡 하나에서 자동화 범위와 개별 설정을 확인한다.
6. **버전 유지:** 최신 필수 입력을 반영한 검증을 별도로 진행하고, 성공한 패키지·가이드·설정 조합을 고정한다.

## 로컬 검사와 CI

- rig-c의 idle 및 hello 빌드와 자체 검사를 실행했다.
- Playwright로 재생과 입력·상태 전환을 확인했다.
- 저장소 제품 코드와 의존성은 변경하지 않았다. 전체 CI·커버리지·OpenCode 통합 테스트는 실행하지 않았다.
- 브랜치 push는 하지 않았으며 GitHub Actions의 품질 게이트 판정은 없다.
