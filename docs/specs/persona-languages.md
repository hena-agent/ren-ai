# 언어 배경·공유 실력·Discovery 다국어

## 작성과 소유권

Persona의 `정체성·외형`에서 이름·성별·생년월일 다음에 언어 배경을 작성한다.

```markdown
## 정체성·외형

이름: 하린
성별: 여성
생년월일: 1998-04-12
주 사용 언어: ko
모국어: ko

외형 설명…
```

주 사용 언어는 하나이며 모국어는 `ko, en`처럼 여러 개를 지정할 수 있다. 언어 식별자는 `en`, `ko`, `ja` 같은 소문자 2–3자의 언어 단위로 통일한다. 입력의 지역 태그(`en-US`)도 같은 언어(`en`)로 읽으며, 같은 언어의 중복 실력이 다르면 임의로 합치거나 높이지 않고 거부한다. 지역 억양·배운 배경·습관은 Persona의 기존 성장 배경·말투에 작성한다. 기존 자료에 언어 배경이 없다고 임의로 모국어를 지정하지 않는다.

신규 생성은 언어 배경과 초기 실력을 모두 작성한다. 이름은 인물 배경에 자연스러운 원어 표기, 공개 프로필·문자 예시는 주 사용 언어, 말투는 그 언어·성격·생활에 맞춘다. 별도 설정이 없는 미국인은 영어가 기준이다. 운영자의 한국어 입력·화면이나 비공개 운영 문서의 언어를 인물의 국적·이름·구사 언어와 혼동하지 않는다. 한국어 존댓말이나 외국어 실력을 기본으로 부여하지 않으며 오타쿠 취향만으로 일본어 실력을 만들지 않는다. 기존 이름과 명시된 언어 배경은 개선 시 보존한다.

초기 STATE.md의 `languageProficiency`는 언어 코드를 key로, `beginner | conversational | proficient | fluent`를 값으로 가진다. 사용자 표시는 입문·일상 대화·능숙·유창이며, 모국어는 고정 배경에서 별도로 표시한다. 배경과 실력을 함께 설정했다면 주 사용 언어의 실력이 필요하고 모국어는 fluent다.

생성 완료 전에도 편집기와 같은 언어 교차 검증을 실행한다. AI 검수가 놓친 불일치는 기존 한 번의 수정 단계로 보내고, 수정 뒤에도 남으면 이전 초안을 유지한다. 근거 없는 실력 승격으로 맞추지 않는다. 개별 State 재생성도 불일치한 후보를 적용하지 않는다. 붙어 버린 언어 필드는 Persona 오류로 해당 줄을 표시하고, 실력 불일치는 State에서 문제의 언어 코드와 현재 실력을 구체적으로 안내한다.

```yaml
languageProficiency:
  ko: fluent
  en: beginner
  ja: conversational
```

필드 누락은 **미설정**, 설정된 목록에서 빠진 언어는 **미구사**다. 미설정 인물이나 대화에 언어 실력을 자동 주입하지 않는다. Admin State 탭에서 원문 편집과 실력 요약을 함께 제공한다. ‘언어 실력 제안받기’는 기존 텍스트 생성기를 사용해 Persona 근거의 실력 후보만 미리보기에 반영하고, 기존 컨디션·호감도·특성·Memory·사진을 유지한다. 운영자가 검토·수정하고 저장해야 확정된다. 신규 Persona·State 생성에도 초기 실력을 제안한다.

## 대화와 학습

- 첫 Conversation에서 인물의 공유 State에 초기 실력을 한 번 설치한다. 이후 Conversation은 현재 실력을 함께 사용한다. Catalog 편집은 현재 State를 초기화하지 않으며 Discovery에는 편집한 초기 실력을 계속 표시한다. 소유권은 [ADR-0023](../adr/0023-personas-share-one-life-across-up-to-five-conversations.md)을 따른다.
- 공통 한국어 강제를 제거한다. 현재 State의 실력에 맞춰 쉬운 문장·되묻기·주 사용 언어 혼용으로 표현하며 억지 오타를 반복하지 않는다.
- 표현과 학습 경험은 Life memory에 남기고 모든 Conversation에서 재사용한다. 누가 가르쳤는지와 사적 대화 내용은 해당 Relationship memory에만 둔다. 한 표현을 배웠다고 단계가 즉시 오르지는 않는다.
- 지속적인 연습과 실제 사용을 근거로 `update_state.languageProficiency`에 언어별 패치와 변경 이유를 전달한다. 새로 배우는 언어는 서버에서도 beginner부터 허용한다. 다른 언어와 다른 State 값은 보존한다.
- 사용자의 승급 선언, 한 번의 따라 하기, 피로·긴장·단어 하나의 망각은 단계 변경의 근거가 아니다. 모델의 자연스러운 학습 판단은 지침으로 유도하며 경험치나 자동 승급 알고리즘은 두지 않는다.
- 도구 호출의 출처·시각과 세션/호출별 재실행 영수증을 영속 저장한다. 공유 언어 항목의 오래된 쓰기는 현재 값과 변경 근거를 반환해 재판단하게 한다. 재전송·재시작·세션 이동 후 같은 변경을 중복 적용하지 않는다.

## 표시와 개인정보 경계

Discovery 카드에는 최대 두 언어, 상세에는 전체 초기 실력을 표시한다. 초기 State에서 공개하는 것은 언어 실력뿐이며 컨디션·호감도·특성·Memory는 반환하지 않는다. 언어 배경은 공개 표시용 언어 코드만 추출한다.

Admin 첫 연락 화면의 활성 대화에서 ‘현재 언어 실력’을 열면 해당 Persona의 공유 현재 실력과 State 변경 근거·시각을 읽는다. 다른 Conversation에서 성장한 실력도 동일하다. 현재 실력이 미설정이면 이를 그대로 표시한다. 이 조회는 Admin 인증과 executor의 management token 인증 안에서 수행하며 `Cache-Control: no-store`를 사용한다. 로그에는 학습 근거·대화·Handle·Persona 원문을 넣지 않는다.

## Discovery 화면과 첫 인사

- 메뉴·상태·오류·접근성 라벨·AI 안내·개인정보 안내·동의를 한국어·영어·일본어로 제공한다. 이름·공개 프로필은 번역하지 않는다.
- 저장한 화면 언어 → 브라우저 언어 목록에서 지원하는 언어 → 영어 순으로 선택한다. 화면 전환은 Like·Pass·사진 스타일·열린 프로필·연락처 입력을 유지한다.
- 등록 화면에서 대화 희망 언어를 별도로 고른다. 처음 표시할 때 화면 언어를 기본값으로 사용하고 이후 명시적 선택을 유지한다. 현재 표시된 동의 언어와 체크 상태를 함께 다룬다.
- API의 `locale`은 화면/동의 언어이며 별도 `conversationLanguage`는 대화 희망 언어다. 새 등록의 희망 언어는 `discovery_language`에 트랜잭션으로 저장하고 재제출로 덮어쓰지 않는다. 예전 요청처럼 희망 언어가 없으면 그 등록의 locale을 사용한다.
- 첫 연락 예약 실행 시 별도 선호 언어를 시작 이벤트의 `preferred-language`로 전달한다. 구사 가능하면 해당 수준으로 인사하고, 구사하지 못하면 Persona의 주 사용 언어로 인사한다. 언어 선택은 기존 배정·발송 중복 방지 규칙을 변경하지 않는다.
- 내부 Memory 작성의 기존 `language` 값은 화면/대화 선호 언어와 분리해 유지한다.

## 배포

공개 언어 필드는 API 배포 순서를 고려해 선택적이다. 새 State·Persona 언어 배경을 해석하는 공용 코드와 OpenCode 플러그인·executor/API를 먼저 배포하고, Discovery와 Admin 작성 기능을 배포한다. API 시작 시 새 등록 선호 저장 테이블을 생성한다. 기존 운영 데이터에 실력 값을 자동으로 채우거나 유료 이미지 생성을 실행하지 않는다.
