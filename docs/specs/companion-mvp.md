# AI 컴패니언 MVP 스펙

## 목표

모바일 웹에서 한 명의 AI 컴패니언을 고르고, iMessage에서 문자와 이미지를 주고받으며 서로 알아가고 관계를 발전시키는 경험을 검증한다. MVP의 **최우선 검증 대상은 Persona Engine**이다. 캐릭터가 자기 삶과 일관된 기본 성격을 지니고, 대화·사건을 통해 새로운 특성이 생기며, 사용자가 그 사람을 서서히 알아가는지를 먼저 확인한다. 호감도 게이지 대신 말과 행동에서 변화를 느끼게 한다.

## 사용자 경험

1. 모바일 웹에서 프로필의 외형, 성격, 관심사, 생활 패턴, 관계관을 살펴본다.
2. **이 사람과 알아가기**를 확정하면 해당 페르소나는 한 사용자에게 전속 배정되고 전체 후보에서 사라진다. 둘러보기만으로는 배정되지 않는다.
3. 웹 계정과 사용자의 iMessage 발신 주소를 연결한다. 연결 전에는 페르소나가 먼저 문자를 보내지 않는다. 연결 후 첫 인사는 페르소나 성향에 따라 사용자 또는 페르소나가 시작한다.
4. 하나의 서비스 iMessage 주소에서 선택한 페르소나와 문자·이미지를 주고받는다. 사용자가 보낸 이미지도 이해해 대화에 반영한다.
5. 알아가기와 썸을 거쳐 사용자와 페르소나 모두 고백·거절할 수 있다. 연애 성사와 관계 종료 모두 가능한 결과다.
6. 관계가 끝나면 해당 페르소나는 기본적으로 다시 노출하지 않는다. 운영자가 검토한 후에만 재등장을 허용할 수 있다. 다음 페르소나를 선택하면 같은 iMessage 스레드를 사용하지만, 새 인물의 시작을 분명히 알리고 이전 관계의 상태·기억을 전달하지 않는다.

서비스는 상대가 AI임을 알린다. 모든 페르소나가 각자 별도 전화번호를 가진 것처럼 설명하지 않는다.

## 내부 모델

| 개념             | 역할                                                | MVP에서 필요한 정보                                                                              |
| ---------------- | --------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| **Persona**      | 인물의 기본 정체성과 생활                           | 이름, 성별, 연락 기대, 시작 관계 단계, 외형 기준, 배경, 말투, 가치관, 취향, 생활 리듬, 선호·경계 |
| **Stat**         | 기본 특성, 변하는 개인 상태, 사용자별 관계 상태     | 성향, 기분·활력·욕구, 친숙함·신뢰·호감의 시작값과 현재값                                         |
| **특성**         | 기존에 숨겨져 있거나 경험으로 새로 생긴 개인적인 면 | 이름·강도, 근거 사건, 나타나는 상황, 지속성, 적용 범위                                           |
| **Memory**       | 실제 대화에서 얻은 지속 정보                        | 사용자에 대해 안 사실, 공유한 사건, 약속, 미해결 화제, 관계의 이력                               |
| **Relationship** | 두 사람 사이의 진행 상태                            | 초면, 알아가기, 친숙함, 썸, 연애, 종료와 그 전환 사건                                            |

- Persona의 기본 성향은 한 번의 대화로 쉽게 바뀌지 않는다. 개인 상태와 관계 Stat은 사건과 시간에 따라 변하고, Memory는 대화에서 확인된 내용을 근거로 형성된다. 새 특성은 실제 경험에 근거해 생기며, 단순한 기분 변화나 원래 있던 숨겨진 특성의 발견과 구분한다. 세부 설계: [Persona Engine](persona-engine.md).
- Stat과 Memory는 사용자 UI에 노출하지 않는다. 변화는 답장 내용, 말투, 연락 주도, 약속에 대한 반응으로 드러난다.
- 기억을 잘못 적용하거나 사용자가 대화에서 정정하면 이후 대화에 반영한다. 화면에서 기억 목록을 직접 편집하는 기능은 MVP에 없다. 계정·대화 데이터 삭제 요청 경로는 별도로 마련한다.
- 관계 변화는 결제 상태나 단순한 메시지 수로 결정하지 않는다. 서비스 한도·기술 장애 때문에 답할 수 없었던 시간도 관계상의 무응답으로 취급하지 않는다.

## 페르소나와 이미지 공급

- Persona Engine의 첫 검증은 **운영자가 수동으로 페르소나와 초기 Stat을 작성**해 시작한다. 전체 MVP에서는 운영자가 AI로 초안을 생성하고 검수해 공개한다. 공개된 한 인물은 동시에 한 사용자만 선택할 수 있다.
- 페르소나마다 외형 기준과 미리 제작한 이미지 묶음을 가진다. 대화에 맞는 이미지가 있으면 이를 보낼 수 있다.
- 대화 맥락에 새로운 이미지가 필요하면 **실시간으로 생성해 iMessage로 전송**한다. 생성 이미지가 해당 페르소나의 외형·상황과 일치하는지 확인하고, 부적합하면 보내지 않고 준비된 이미지나 텍스트로 응답한다.
- 사용자가 직접 페르소나를 만들어 공개 후보로 등록하는 기능은 후속 단계다. 향후 제작자도 자신이 등록한 후보를 선택할 수 있다.

## 첫 버전의 운영 범위

- **구현 우선순위 1: Persona Engine.** 운영자 작성·검수 → 텍스트 대화/사건 시뮬레이션 → 상태·기억·특성 형성의 기록과 재사용을 먼저 검증한다. 이후 모바일 웹 탐색·선택, iMessage 및 이미지 전송을 연결한다. 이 순서는 전체 MVP 범위를 줄이는 결정이 아니다.
- 초기 채널은 **하나의 iMessage 주소**다. 웹 계정·발신 주소·배정된 페르소나를 연결해 사용자별 대화를 분리한다. 주소 변경 시 재연결이 필요하다.
- 모바일 웹은 탐색·선택·연결 및 계정 관리에 집중한다. 별도의 웹 채팅 화면은 MVP의 중심이 아니다.
- 문자, 준비된 이미지 발신, 실시간 이미지 생성·발신, 사용자 이미지 수신·이해를 포함한다. 음성·통화는 후속 단계다.
- 이미지가 오가는 실제 iMessage 연결의 수신·전송 및 페르소나별 대화 분리는 구현 초기에 실기기로 검증한다. 공개된 일반 봇용 iMessage 서버 API는 없다. 관련 조사: [Instinct iMessage 메모](instinct-imessage-research.md).
- 안전한 응답, AI 정체성 고지, 개인 대화의 접근 제한과 삭제 경로는 초기 경험에 포함한다.

## 검증 기준과 남은 결정

**우선 검증:** 같은 사건에도 후보들이 서로 다른 사람처럼 반응하는가; 새로운 특성이 근거 있는 경험에서만 생기고 이후 대화에 일관되게 반영되는가; 숨겨진 특성의 발견·일시적 기분·새 특성 형성이 구분되는가; 캐릭터의 생활과 사용자별 기억·관계 상태가 섞이지 않는가.

**전체 MVP 검증:** 전속 선택이 이해되는가; 준비된 이미지와 실시간 생성 이미지가 같은 인물로 보이는가; iMessage 문자·사진이 누락이나 대화 혼선 없이 오가는가.

**후속 결정:** 무료 체험의 기간·누적 대화량, 가격·구독 범위, 이미지 사용량과 과금, 연령 정책, 사용자 제작 도구와 공개 심사 기준. 과금은 연애 성사 여부가 아니라 무료 체험 후 지속적인 연락과 분리해 설계한다는 방향만 정해져 있다. 관련 결정: [과금 방향](companion-monetization.md).
