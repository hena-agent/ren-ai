# Persona Engine 개발 스펙

인물 모델: [Persona Engine](persona-engine.md). MVP에서는 이 엔진을 먼저 검증한 뒤 채널과 이미지를 연결한다.

## 작업 목록

- [x] `packages/persona-engine`에 빌드 없는 JIT 패키지(`@ren-ai/persona-engine`)를 만든다. 웹·저장소·특정 모델 공급자에 의존하지 않는다.
- [x] 운영자 정의(서술형 Persona, 기본/현재/관계 시작 Stat, 숨겨진 특성)로 독립된 세션을 생성한다. 기본 특성은 대화에서 수정할 수 없다.
- [x] 한 턴의 입력(사용자 메시지 또는 운영자가 확정한 생활 사건)과 현재 상태에서 모델이 응답·변경안을 제안한다. 엔진은 검증한 뒤 다음 상태·응답·변경 이력을 반환한다.
- [x] 새 특성에는 이름·강도·근거 사건 ID·형성 이유·나타나는 상황·지속성(상황 한정/지속)·적용 범위(사용자/생활 전반)를 기록한다. 숨겨진 면의 발견과 기분 변화를 새 특성으로 저장하지 않는다.
- [x] 근거 없는 특성, 범위 밖 수치, 다른 세션의 사건 ID, 잘못된 AI 결과는 거부하고 이전 상태를 유지한다. 재시도에 대비해 입력 ID의 중복 적용을 막는다.
- [x] `apps/persona-lab`에서 하린·지우의 대화를 로컬 웹으로 체험한다. 대화 옆에서 Stat·특성·사건 근거를 확인하고 필요할 때 명시적으로 초기화·기록 내려받기·불러오기가 가능해야 한다.
- [x] 테스트를 위해 한 페르소나에 여러 세션을 만들고 골라서 이어갈 수 있다. 실제 제품에서는 한 사용자·한 캐릭터가 한 세션이지만, Lab은 비교 실험을 위해 세션을 임의로 늘릴 수 있다.
- [x] 페르소나마다 `speech`/`samples`로 말투를 정의하고, Gemini가 실제 사람처럼 짧게 문자하게 한다. 단계는 정보 경계만 정하고 말투를 정하지 않는다. 존댓말/반말은 말 놓기 합의로만 바뀐다.
- [x] 같은 캐릭터를 다시 선택하거나 서버를 재시작해도 세션·판단 기록·다음 평가 시각을 이어간다. 사용자가 바뀌는 제품 단계에서는 관계와 사용자 기억을 분리한다.
- [x] Jev를 상태 전이 함수로 사용한다. 사용자 메시지마다, 그리고 5분마다 상태를 평가한다. 응답하지 않기로 해도 Jev가 근거 있는 상태 변화를 판단하면 적용한다. 보낼 때만 Gemini가 문장을 만든다.
- [x] 관계 단계를 명시적 상태로 저장한다. 초면·알아가기·친숙함·썸·연애·종료의 사다리, 단계별 게이트와 관계 상한, 한 단계 전진, 초기 구간의 하향, 썸·연애에서의 종료 직행, 종료 후 발신 없음을 구현한다.

## 첫 구현의 Interface

`createSession(definition, personaId)`는 원본을 변경하지 않는 초기 상태를 만든다. `recordInput`은 답장을 강제하지 않고 사건을 저장하고, `emit`은 Jev가 발송하기로 판단했을 때만 Gemini의 문장·변경안을 적용한다. 입력 ID는 호출자가 주고 응답 ID는 실행 시 결정한다. 실험실은 턴별 입력·모델 응답을 저장하고 재시작 시 처음부터 재실행해 검증한다.

Jev는 Vercel AI Gateway의 `typesafe-ai/jev` 평가 모델이다. 한 번의 평가에서 발송 행동, 의미 있는 연락 기대 위반 여부, 개인 상태·관계·가변 성격의 각 축이 감소/유지/증가하는지를 선택한다. 엔진은 선택을 작은 변화량으로 적용하고 0~100에 묶는다. Gemini는 Jev가 전이한 상태를 읽어 문장만 작성하며 Stat을 변경할 수 없다. 키는 브라우저에 보내지 않는다. AI 호출 실패는 판단 이력에 오류로 남기고 사용자 입력과 이미 적용한 Jev 전이는 보존한다.

기본 성향은 고정한다. 가변 성격은 `자기 개방 / 방어적 태도 / 관계 주도 의향`의 고정된 축으로 시작하며, 새로운 이름의 특성 생성은 후속 단계다. 성별과 연락 기대는 인물의 서술형 설정으로 Jev에 전달한다. 성별만으로 변화량을 정하지 않는다. 5분은 **재평가 간격**이지 변화 간격이 아니다. 시간 경과만으로 같은 서운함을 중복 누적하지 않고, 마지막 연락을 기준으로 30분·2시간·1일의 새 시간 구간에서만 변화가 가능하다. Jev가 기대 위반을 판단하지 않으면 서운함·관계·가변 성격은 유지한다. 기술 장애로 인한 무응답은 서운함의 근거로 사용하지 않는다.

관계 단계는 엔진(`packages/persona-engine/src/stages.ts`)이 순서·게이트·상한·전환 규칙을 소유하고, 실험실의 전이 composer가 관계 상한으로 clamp한 뒤 게이트를 통과한 단계 변경을 덧붙인다. 단계는 사건 기반 사용자 메시지에서만 바뀐다. 단계 지침은 `아는 척 금지` 같은 정보 경계이며, 말투는 페르소나의 `speech`/`samples`가 담당한다. 둘 다 Jev 컨텍스트와 Gemini 프롬프트에 전달한다.

Gemini는 실제 사람이 메신저로 문자하듯 쓴다. 한두 개의 짧은 메시지를 줄바꿈으로 구분해 보내고, 항상 질문으로 끝내지 않으며, 상담원 말투와 지어낸 시각·장소·과거를 금지한다. 기본은 존댓말이고, 둘이 말 놓기에 합의했을 때만 반말로 바뀐다. Jev는 연속된 사용자 메시지를 하나의 발화로 보고 함께 답하도록 지시받는다.

## 로컬 실행

`bun install` 후 `apps/persona-lab/.env`에 `GEMINI_API_KEY`와 `AI_GATEWAY_API_KEY`를 입력하고 저장소 루트에서 `bun run dev`를 실행해 `http://127.0.0.1:3000`에 접속한다. `.env`는 Git에서 제외하며 `.env.example`은 설정 예시다. `GEMINI_MODEL`(기본값 `gemini-2.5-flash`)과 `GEMINI_BASE_URL`은 선택 사항이다. Lab에서는 `시간 진행`으로 Jev의 다음 판단을 곧바로 시험할 수 있고, `새 세션`으로 같은 페르소나의 독립된 세션을 만들어 목록에서 골라 이어갈 수 있다. 세션은 `apps/persona-lab/data/{세션 ID}.json`에 보관되며, 버튼으로 명시적으로 초기화할 수 있다.

서버를 시작하면 터미널에 접속 주소·Jev/Gemini 키 설정 여부·Gemini 모델 이름이 출력된다. 터미널을 열어 둔 채 브라우저에서 접속한다. 판단마다 캐릭터·트리거·선택·소요 시간과 실패 이유를 출력하며, API 키나 대화 내용은 로그에 남기지 않는다. 서버 종료는 `Ctrl+C`.

## 검증 시나리오

- [ ] 실제 Jev와 Gemini로 여러 턴을 실행해 하린과 지우의 인물 차이를 평가한다.
- [x] 일상 대화는 새 특성 없이 끝날 수 있고, 상태 변화는 기본 성격을 덮어쓰지 않는다.
- [x] 숨겨진 특성의 발견은 기존 특성의 드러남으로 기록되고 새 특성으로 중복되지 않는다.
- [x] 실제 사건을 근거로 상황 한정 특성이 생기고 다른 사건을 거치면 지속 특성으로 변경할 수 있다.
- [x] 근거·범위·강도 오류와 중복 입력은 적용하지 않는다. AI 호출 실패는 이미 접수한 사용자 메시지를 보존하고 판단 실패를 기록한다.
- [x] 서로 다른 캐릭터의 상태가 섞이지 않고, 저장한 입력·Gemini 결과로 재시작 시 상태를 복원한다. 자동 테스트에서는 네트워크 없이 모델 결과를 주입한다.
- [x] 사용자 메시지에서 답장을 보내지 않아도 Jev 전이가 기록된다. 정기 평가는 같은 시간 구간에서 상태를 반복해서 변화시키지 않는다.
- [x] 단계 전환은 게이트를 충족할 때만 인접 한 단계로 일어나고, 건너뛰기·비인접 전환은 거부된다. 관계 상한이 단계를 앞질러 가지 못하게 막는다.
- [x] 초면·알아가기·친숙함에서만 하향이 가능하고, 썸·연애에서는 하향 대신 종료로 간다. 종료 후에는 발신하지 않는다.
- [x] 저장된 단계 변경을 재생으로 복원한다. 종료는 되돌릴 수 없다.
- [ ] 사용자에게 보낸 실제 발신 메시지까지 시간 기반 관계 전이에 연결해, 상대의 무응답을 맥락대로 평가한다.
- [ ] 대화에서 얻은 사실·약속을 사건 이력과 별도 Memory로 정리하고 정정·분리한다.
- [ ] 사건 시각과 Persona 정의 버전을 기록해 시간이 지나도 같은 기록을 정확히 재현한다.

패키지는 저장소의 파일별 커버리지 100%, 생존 mutant 0, 타입·린트·중복 검사 등을 통과해야 한다. 로컬 실모델 평가는 비결정적이므로 CI에 넣지 않는다.
