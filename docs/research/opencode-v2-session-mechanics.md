# OpenCode V2 session mechanics for iMessage personas (v2.0.16)

## Answer

For a conversation-bound persona, a persistent session can accept inbound messages during a turn: use `delivery: "steer"` to make them visible at the **next step boundary**, or `"queue"` for the **next turn**. Neither rewrites an already-sent LLM request. `resume: false` records input in a durable pending inbox, **not** yet in model-visible history. The embedded host automatically resumes orphaned turns, but an interrupted tool is marked aborted and a **new model step** decides what to do next; neither a tool call ID nor OpenCode's database makes an iMessage send exactly once. Keep inbound-event IDs and outbound-action/idempotency state in the host, and reconcile both pending inbox and stored messages on restart. These are implications of the source, not a tested deployment policy. [Prompt admission](https://github.com/anomalyco/opencode/blob/v2.0.16/packages/core/src/session/session.ts#L146-L179) · [inbox promotion](https://github.com/anomalyco/opencode/blob/v2.0.16/packages/core/src/session/inbox.ts#L490-L531) · [recovery](https://github.com/anomalyco/opencode/blob/v2.0.16/packages/core/src/session/execution/restart.ts#L46-L61) · [stale calls](https://github.com/anomalyco/opencode/blob/v2.0.16/packages/core/src/session/runner/llm.ts#L332-L355).

## 1. Prompting a busy session

- `prompt({ text, id?, metadata?, delivery?, resume? })` admits a **separate durable inbox item** and wakes the per-session execution; default delivery is `steer`, not `queue`. The public endpoint passes these options through. Reusing the same message ID reconciles an existing pending or delivered user item instead of preparing it again; a mismatched ID/type conflicts. [prompt](https://github.com/anomalyco/opencode/blob/v2.0.16/packages/core/src/session/session.ts#L146-L179) · [reconciliation](https://github.com/anomalyco/opencode/blob/v2.0.16/packages/core/src/session/inbox.ts#L113-L166) · [HTTP handler](https://github.com/anomalyco/opencode/blob/v2.0.16/packages/server/src/handlers/session.ts#L304-L339).
- At a continuing turn's **next LLM-step boundary**, the runner promotes pending steers, potentially **several distinct prompts together**, then reloads history and calls the model. Queued inputs wait for an idle/next-turn boundary, where one queue item (plus available steers) is promoted. There is no insertion into an in-flight provider request; a tool that sleeps for 20 minutes delays that boundary. `session.inbox.update` changes a *still pending* item's delivery, and `session.inbox.cancel` cancels it. [runner](https://github.com/anomalyco/opencode/blob/v2.0.16/packages/core/src/session/runner/llm.ts#L77-L86) · [runner](https://github.com/anomalyco/opencode/blob/v2.0.16/packages/core/src/session/runner/llm.ts#L160-L193) · [promotion](https://github.com/anomalyco/opencode/blob/v2.0.16/packages/core/src/session/inbox.ts#L490-L531) · [endpoints](https://github.com/anomalyco/opencode/blob/v2.0.16/packages/server/src/handlers/session.ts#L532-L561).
- “Coalesce” describes **wake/doorbell notifications and one busy-period drain**, not merging text or discarding input. Repeated wakes retain the broadest scope; one session has one process-local execution fiber. To see fresh input *before* the current tool/LLM finishes, explicitly interrupt and then resume/steer; this has cancellation and side-effect implications below. [coordinator](https://github.com/anomalyco/opencode/blob/v2.0.16/packages/core/src/session/run-coordinator.ts#L31-L45) · [wake](https://github.com/anomalyco/opencode/blob/v2.0.16/packages/core/src/session/run-coordinator.ts#L124-L145) · [interrupt/resume](https://github.com/anomalyco/opencode/blob/v2.0.16/packages/core/src/session/execution.ts#L153-L176).

## 2. Cancelling a turn

- Call `session.interrupt(sessionID, { resume?: boolean })` (HTTP `POST /api/session/{sessionID}/interrupt?resume=...`); `resume: true` wakes eligible steer/control work after interruption, **not** a queued next-turn prompt. Interrupt acknowledges before finalizers/settlement; `session.wait` waits for idle (and successors). A new prompt can be admitted immediately; a run/join during cleanup waits then starts afresh. [session](https://github.com/anomalyco/opencode/blob/v2.0.16/packages/core/src/session/session.ts#L266-L319) · [execution](https://github.com/anomalyco/opencode/blob/v2.0.16/packages/core/src/session/execution.ts#L156-L176) · [coordinator](https://github.com/anomalyco/opencode/blob/v2.0.16/packages/core/src/session/run-coordinator.ts#L114-L175) · [route](https://github.com/anomalyco/opencode/blob/v2.0.16/packages/client/src/promise/generated/client.ts#L947-L959) · [handler](https://github.com/anomalyco/opencode/blob/v2.0.16/packages/server/src/handlers/session.ts#L610-L614).
- **Promise-style** plugin tool context has an `AbortSignal`, wired to the interruptible Effect promise; on a live interruption it is signalled, though a tool must cooperate to stop its own external work. The Effect-native context has no `signal` field; use Effect interruption. On a hard crash there is no running process to receive an abort signal. [Promise context](https://github.com/anomalyco/opencode/blob/v2.0.16/packages/plugin/src/promise/tool.ts#L1-L21) · [adapter](https://github.com/anomalyco/opencode/blob/v2.0.16/packages/plugin/src/promise/adapter.ts#L609-L622) · [Effect context](https://github.com/anomalyco/opencode/blob/v2.0.16/packages/schema/src/tool.ts#L11-L20) · [tool fibers](https://github.com/anomalyco/opencode/blob/v2.0.16/packages/core/src/session/runner/step.ts#L135-L145).
- Streamed text/reasoning, assistant step, and tool input/call are already recorded as events; cancellation flushes fragments, fails unsettled calls with an `aborted` error, and marks the assistant step interrupted/failed when the attempt reaches its finalizer. If death interrupts those finalizers, the projected assistant can remain **incomplete**, and a subsequent drain marks stale streaming/running tools aborted instead. The session gets an interrupted idle outcome for deliberate interruption. [step](https://github.com/anomalyco/opencode/blob/v2.0.16/packages/core/src/session/runner/step.ts#L190-L243) · [event publisher](https://github.com/anomalyco/opencode/blob/v2.0.16/packages/core/src/session/runner/publish-llm-event.ts#L325-L379) · [stale tools](https://github.com/anomalyco/opencode/blob/v2.0.16/packages/core/src/session/runner/llm.ts#L332-L355) · [message projection](https://github.com/anomalyco/opencode/blob/v2.0.16/packages/core/src/session/message-updater.ts#L214-L285).

## 3. Adding history without running a turn

- **Yes, with an important distinction:** `session.prompt({ resume: false })` and `session.synthetic({ resume: false })` durably **stage** user or synthetic input; it appears in `session.inbox` until promotion by a later wake/resume, then becomes a user/synthetic message. This is not V1-style immediate history append. Synthetic text is model-facing **user** content, not assistant content; the public prompt/synthetic methods do not offer an arbitrary assistant-message insert. [session](https://github.com/anomalyco/opencode/blob/v2.0.16/packages/core/src/session/session.ts#L146-L179) · [synthetic](https://github.com/anomalyco/opencode/blob/v2.0.16/packages/core/src/session/session.ts#L274-L315) · [projection](https://github.com/anomalyco/opencode/blob/v2.0.16/packages/core/src/session/projector.ts#L609-L639) · [lowering](https://github.com/anomalyco/opencode/blob/v2.0.16/packages/core/src/session/runner/to-llm-message.ts#L266-L302).
- A plugin `context` hook **can** insert model-request-only assistant/user/system messages, but does not write them to stored session history. A server could render an external transcript in a new session's prompt, but native append/import of arbitrary assistant-side messages into an existing session is **unconfirmed** as a supported incremental API; the separate `session.import` endpoint accepts an entire transferred session. [request hook](https://github.com/anomalyco/opencode/blob/v2.0.16/packages/plugin/src/effect/session.ts#L25-L35) · [hook path](https://github.com/anomalyco/opencode/blob/v2.0.16/packages/core/src/session/model-request.ts#L206-L254) · [import](https://github.com/anomalyco/opencode/blob/v2.0.16/packages/server/src/handlers/session.ts#L142-L175).

## 4. Compaction

- Automatic compaction defaults **on**, with a 20,000-token buffer and 15,000-token recent-context allowance. Before each primary step, it compares estimated used tokens with the model's input/context ceiling minus buffer/reserved output; eligible context-overflow failures can trigger a recovery compaction as well. Project `opencode.jsonc` can set `compaction.auto`, `compaction.buffer`, and `compaction.keep.tokens`; `auto: false` disables automatic compaction but not the explicit control. [defaults/threshold](https://github.com/anomalyco/opencode/blob/v2.0.16/packages/core/src/session/compaction.ts#L40-L44) · [settings](https://github.com/anomalyco/opencode/blob/v2.0.16/packages/core/src/session/compaction.ts#L395-L415) · [required](https://github.com/anomalyco/opencode/blob/v2.0.16/packages/core/src/session/compaction.ts#L736-L763) · [config](https://github.com/anomalyco/opencode/blob/v2.0.16/packages/core/src/config/plugin/compaction.ts#L9-L25) · [runner](https://github.com/anomalyco/opencode/blob/v2.0.16/packages/core/src/session/runner/llm.ts#L204-L226).
- Local compaction creates a structured summary **plus a serialized recent tail**, selected near a user boundary; tool outputs included in that serialized tail are truncated to 2,000 characters. The following request starts at the latest completed compaction and sends its checkpoint plus newer messages; earlier messages remain in stored history accessible through `session.messages`. Some configured providers use a native replacement window instead of the local text summary. This is **not** a guarantee of verbatim recent tool results after compaction. [tail](https://github.com/anomalyco/opencode/blob/v2.0.16/packages/core/src/session/compaction.ts#L279-L361) · [checkpoint](https://github.com/anomalyco/opencode/blob/v2.0.16/packages/core/src/session/runner/to-llm-message.ts#L301-L325) · [history boundary](https://github.com/anomalyco/opencode/blob/v2.0.16/packages/core/src/session/history.ts#L16-L60) · [native branch](https://github.com/anomalyco/opencode/blob/v2.0.16/packages/core/src/session/compaction.ts#L735-L740).
- The built-in summary template/rules and model selection are not a documented per-agent `compaction` prompt/model setting: compaction resolves the **current session agent/model** and uses a fixed appended template. A plugin `session.hook("compaction", ...)` can rewrite its system/messages/options or set `event.result` to supply the summary and skip the model call (the fixed summary instruction is appended **after** that hook if generating locally). `session.compact()` explicitly enqueues a compaction control; plugin hooks for `context` and `compaction` are distinct. [manual path](https://github.com/anomalyco/opencode/blob/v2.0.16/packages/core/src/session/runner/llm.ts#L109-L143) · [prompt/template](https://github.com/anomalyco/opencode/blob/v2.0.16/packages/core/src/session/compaction.ts#L364-L390) · [hook/result](https://github.com/anomalyco/opencode/blob/v2.0.16/packages/core/src/session/compaction.ts#L620-L631) · [hook type](https://github.com/anomalyco/opencode/blob/v2.0.16/packages/plugin/src/effect/session.ts#L38-L48) · [method](https://github.com/anomalyco/opencode/blob/v2.0.16/packages/core/src/session/session.ts#L247-L265).

## 5. The `context` hook

- The hook receives mutable `system: SystemPart[]`, **`messages: Message[]`**, `options`, `tools`, and readonly `sessionID`, `model`, `agent`. It runs **for each primary model-request preparation** (including continuing steps), not just at session creation; it can filter/insert/reorder messages or rewrite the system, options, and advertised tool definitions for that request. Persona's existing plugin filters only `event.system`, although the hook offers more. Hook transformations do **not** themselves change durable history. [types](https://github.com/anomalyco/opencode/blob/v2.0.16/packages/plugin/src/effect/session.ts#L22-L35) · [request construction](https://github.com/anomalyco/opencode/blob/v2.0.16/packages/core/src/session/model-request.ts#L206-L254) · [per-step invocation](https://github.com/anomalyco/opencode/blob/v2.0.16/packages/core/src/session/runner/llm.ts#L227-L248).
- Other session hooks: `prompt`, `compaction`, `generate`, `title`, `model.request`, `http.request`, `http.response`, `experimental.ws.handshake`, `experimental.ws.send`, `experimental.ws.receive`, and `retry`. Separate tool hooks are `execute.before` and `execute.after`. [session hook registry](https://github.com/anomalyco/opencode/blob/v2.0.16/packages/plugin/src/effect/session.ts#L138-L151) · [tool hooks](https://github.com/anomalyco/opencode/blob/v2.0.16/packages/plugin/src/effect/tool.ts#L20-L51).

## 6. Restart recovery and exactly-once boundaries

- Admission commits a pending inbox row; promotion consumes that row **in the same event transaction** as creation of a visible user/synthetic message. An execution claim is committed with the started event and normally released with the terminal event; graceful host shutdown retains it. The embedded SDK forks the recovery sweep **immediately on host creation**, without waiting for app startup to finish. [inbox rows](https://github.com/anomalyco/opencode/blob/v2.0.16/packages/core/src/session/inbox.ts#L277-L335) · [promotion projection](https://github.com/anomalyco/opencode/blob/v2.0.16/packages/core/src/session/projector.ts#L609-L655) · [claim/terminal](https://github.com/anomalyco/opencode/blob/v2.0.16/packages/core/src/session/execution.ts#L79-L88) · [claim/terminal](https://github.com/anomalyco/opencode/blob/v2.0.16/packages/core/src/session/execution.ts#L114-L149) · [SDK boot](https://github.com/anomalyco/opencode/blob/v2.0.16/packages/sdk/src/internal/host.ts#L48-L53).
- A provider step publishes `Step.Started`, text/reasoning fragments, tool input/call **before local execution**, tool progress/success/failure as they happen, and `Step.Ended`/`Step.Failed` after tool settlement; each event projects into persistent assistant parts. A call can therefore succeed externally before its success is durably recorded. [publisher](https://github.com/anomalyco/opencode/blob/v2.0.16/packages/core/src/session/runner/publish-llm-event.ts#L99-L119) · [tool-call publication](https://github.com/anomalyco/opencode/blob/v2.0.16/packages/core/src/session/runner/publish-llm-event.ts#L441-L457) · [tool success](https://github.com/anomalyco/opencode/blob/v2.0.16/packages/core/src/session/runner/publish-llm-event.ts#L556-L573) · [step settlement](https://github.com/anomalyco/opencode/blob/v2.0.16/packages/core/src/session/runner/step.ts#L218-L244) · [projection](https://github.com/anomalyco/opencode/blob/v2.0.16/packages/core/src/session/message-updater.ts#L214-L285).
- On restart the sweep increments durable resume attempts (default max **10**), appends a synthetic restart notice, and resumes claimed top-level sessions asynchronously. The runner marks stale `streaming`/`running` tools **aborted** and loads history for a **fresh LLM step**. It does **not** re-execute that old call with the old ID; the model may generate another call (a new ID), retry a send, or continue differently. Previously recorded successful tools remain in history; a crash in the gap after an external send and before durable tool success is fundamentally ambiguous. A 20-minute sleep dies with the process and is not resumed where it left off. [recovery](https://github.com/anomalyco/opencode/blob/v2.0.16/packages/core/src/session/execution/restart.ts#L23-L33) · [recovery](https://github.com/anomalyco/opencode/blob/v2.0.16/packages/core/src/session/execution/restart.ts#L75-L99) · [sweep](https://github.com/anomalyco/opencode/blob/v2.0.16/packages/core/src/session/execution/restart.ts#L192-L230) · [stale tools](https://github.com/anomalyco/opencode/blob/v2.0.16/packages/core/src/session/runner/llm.ts#L332-L355) · [fresh step ID](https://github.com/anomalyco/opencode/blob/v2.0.16/packages/core/src/session/runner/llm.ts#L204-L214).
- A plugin tool does receive `context.id` (the provider tool-call ID) and `context.messageID` (assistant step ID); these identify **that published call**, not a stable logical send across new LLM steps. No documented `OpenCode.create()` recovery-disable/filter/delay option or pre-sweep host callback appears in its options/path; the core restart service has a `maxAttempts` layer option and an inert `resumeSuspendedSessions` method for **custom embedders**, but the standard SDK wires and forks its default service. Calling `session.interrupt` from application startup is **not a reliable pre-sweep barrier**. Exact once requires a host-controlled durable outbound action key/ledger and provider/iMessage-side reconciliation, not call-ID dedupe alone. [tool ID](https://github.com/anomalyco/opencode/blob/v2.0.16/packages/core/src/tool.ts#L263-L270) · [SDK options/boot](https://github.com/anomalyco/opencode/blob/v2.0.16/packages/sdk/src/internal/host.ts#L17-L25) · [SDK boot](https://github.com/anomalyco/opencode/blob/v2.0.16/packages/sdk/src/internal/host.ts#L48-L53) · [restart extension](https://github.com/anomalyco/opencode/blob/v2.0.16/packages/core/src/session/execution/restart.ts#L23-L75) · [at-least-once warning](https://github.com/anomalyco/opencode/blob/v2.0.16/packages/core/src/session/execution/restart.ts#L46-L59).

## 7. Tool execution and plain text

- The **generic plugin tool** execution path has no hardcoded elapsed-time limit; the runner waits for tool fibers after reading the provider stream. A 30+-minute wait can therefore be valid while the host remains alive, subject to process/network/transport/tool-specific limits (**unconfirmed** for any specific provider or macOS sleep policy). Promise tools should honor their abort signal. [generic runtime](https://github.com/anomalyco/opencode/blob/v2.0.16/packages/core/src/tool/runtime.ts#L28-L60) · [runner join](https://github.com/anomalyco/opencode/blob/v2.0.16/packages/core/src/session/runner/step.ts#L100-L145) · [Promise adapter](https://github.com/anomalyco/opencode/blob/v2.0.16/packages/plugin/src/promise/adapter.ts#L615-L622).
- Tool results can return arbitrary **string text** via `content` (or typed `output` with an output schema); they must produce normalized nonempty content and large text is truncated to a configurable default **2,000 lines / 50 KiB**, with full text saved to a file. A tool has no documented “finish this turn” control; calling `session.interrupt` separately is cancellation, not successful completion. A normal local tool call generally causes a further LLM step unless max-step policy disables tools. [tool result](https://github.com/anomalyco/opencode/blob/v2.0.16/packages/schema/src/tool.ts#L67-L102) · [normalization](https://github.com/anomalyco/opencode/blob/v2.0.16/packages/core/src/tool/runtime.ts#L28-L60) · [truncation](https://github.com/anomalyco/opencode/blob/v2.0.16/packages/core/src/tool-output.ts#L13-L16) · [continuation](https://github.com/anomalyco/opencode/blob/v2.0.16/packages/core/src/session/runner/publish-llm-event.ts#L591-L600) · [step](https://github.com/anomalyco/opencode/blob/v2.0.16/packages/core/src/session/runner/step.ts#L264-L266).
- Assistant plain text (without a tool call) is persisted as an assistant text part; with no continuation work, the run settles. Nothing in the runner sends that text over iMessage: an external host must explicitly decide whether and how to deliver it, or instruct/use a conversation-bound `send` tool. This last iMessage conclusion follows from the tool and step paths rather than an iMessage integration in OpenCode. [text publication](https://github.com/anomalyco/opencode/blob/v2.0.16/packages/core/src/session/runner/publish-llm-event.ts#L199-L221) · [text projection](https://github.com/anomalyco/opencode/blob/v2.0.16/packages/core/src/session/message-updater.ts#L288-L300) · [continuation decision](https://github.com/anomalyco/opencode/blob/v2.0.16/packages/core/src/session/runner/step.ts#L264-L266).

## 8. Session metadata and lifecycle

- `session.update` can **replace** session metadata after creation (also title/permissions); `session.get` returns it. Listing filters by directory/project/workspace, parent, title search, and cursor/limit/order, **not arbitrary metadata**. Fork copies the parent's metadata, agent/model/permissions and settled history up to an optional `before` message; a **new empty session with a server-provided summary** is another rotation approach. [update](https://github.com/anomalyco/opencode/blob/v2.0.16/packages/server/src/handlers/session.ts#L255-L278) · [replace projection](https://github.com/anomalyco/opencode/blob/v2.0.16/packages/core/src/session/projector.ts#L576-L583) · [list](https://github.com/anomalyco/opencode/blob/v2.0.16/packages/core/src/session/store.ts#L17-L39) · [list filters](https://github.com/anomalyco/opencode/blob/v2.0.16/packages/core/src/session/store.ts#L99-L139) · [fork](https://github.com/anomalyco/opencode/blob/v2.0.16/packages/core/src/session/projector.ts#L147-L196).
- `session.remove` deletes a session after interrupt/wait, including child sessions; `session.fork` creates a separate top-level session with copied history. The schema contains `time.archived`, but no archive/unarchive operation appears in the 2.0.16 session service/handler, and list does not exclude archived rows; **archiving via public session API is unconfirmed**. ## 9. Cost of a long-lived session

- **Yes, each model request rebuilds and sends the whole currently selected post-compaction history** (not all pre-checkpoint rows), together with system and tools. There is no generic continuous pruning of *old* tool outputs before the threshold; there is output truncation on tool completion and summary-tail truncation *during compaction*. Growth between compactions still consumes context and can increase latency/cost. [history](https://github.com/anomalyco/opencode/blob/v2.0.16/packages/core/src/session/history.ts#L78-L115) · [runner request](https://github.com/anomalyco/opencode/blob/v2.0.16/packages/core/src/session/runner/llm.ts#L227-L248) · [tool output limit](https://github.com/anomalyco/opencode/blob/v2.0.16/packages/core/src/tool-output.ts#L65-L120) · [summary truncation](https://github.com/anomalyco/opencode/blob/v2.0.16/packages/core/src/session/compaction.ts#L258-L310).
- Provider prompt caching is supported, **not guaranteed to hit**: OpenCode supplies session-affine `promptCacheKey`; the AI layer defaults to automatic cache breakpoints for routes that accept inline hints (e.g. Anthropic), while OpenAI/Gemini rely on provider-side implicit caching. Cache hit/billing depends on model/provider, stable prefix, TTL and request shape. [session affinity](https://github.com/anomalyco/opencode/blob/v2.0.16/packages/core/src/session/model-request.ts#L237-L259) · [cache policy](https://github.com/anomalyco/opencode/blob/v2.0.16/packages/ai/src/cache-policy.ts#L1-L45) · [breakpoints](https://github.com/anomalyco/opencode/blob/v2.0.16/packages/ai/src/cache-policy.ts#L150-L164).

## 10. Reading history and delivery reconciliation

- `session.messages` paginates **all persisted messages** (including older-than-compaction messages), with optional message-type filter; `session.message` looks up a known ID. `session.context` only exposes the selected post-compaction context; `session.inbox` lists still-pending user/synthetic items. User-message `metadata` is preserved on promotion and returned with message content/parts. For inbound event dedupe, assign a stable OpenCode `msg_...` ID and/or metadata; check **both** inbox and delivered message, since `resume: false` or a busy step leaves items pending. [message endpoint](https://github.com/anomalyco/opencode/blob/v2.0.16/packages/server/src/handlers/message.ts#L32-L62) · [storage reads](https://github.com/anomalyco/opencode/blob/v2.0.16/packages/core/src/session/store.ts#L140-L192) · [pending](https://github.com/anomalyco/opencode/blob/v2.0.16/packages/core/src/session/inbox.ts#L386-L395) · [projection](https://github.com/anomalyco/opencode/blob/v2.0.16/packages/core/src/session/projector.ts#L609-L638) · [message schema](https://github.com/anomalyco/opencode/blob/v2.0.16/packages/schema/src/session-message.ts#L23-L35).
- Prefer the provided stable ID to a read-then-write dedupe race: `prompt` reconciles that ID against inbox **or already promoted history**. But this dedupes *OpenCode user admission only*, not an outbound send (which might have happened before tool success was persisted). OpenCode's in-process session log can replay durable events by sequence; its live event stream alone need not be relied upon for reconciliation. [prompt reconcile](https://github.com/anomalyco/opencode/blob/v2.0.16/packages/core/src/session/inbox.ts#L113-L166) · [session log contract](https://github.com/anomalyco/opencode/blob/v2.0.16/packages/core/src/session.ts#L149-L169) · [recovery semantics](https://github.com/anomalyco/opencode/blob/v2.0.16/packages/core/src/session/execution/restart.ts#L46-L59).
