# Mac mini operations

## Development resets

Run `XDG_STATE_HOME=/Users/chris/.local/state/ren-ai /Users/chris/.bun/bin/bun run packages/api-msg.hena.dev/src/operator-entry.ts test-handle HANDLE` to mark a test handle, before or after onboarding. Use `untest-handle HANDLE` to unmark it. Changes apply immediately and marks survive User removal.

From a marked handle, text `/reset` (case-insensitive, surrounding whitespace allowed). The service sends the Notice and starts a new session with a fresh Greeting. Earlier sessions stay readable in the OpenCode Web UI with `· reset TIME` in their titles. The new session appears separately with the usual title. Rebuilds never restore pre-reset memory. From an unmarked handle, `/reset` is ordinary text; editing a message into the command does not execute it.

`remove HANDLE` preserves a test handle's sessions and marks the current one `· removed TIME`. To delete all sessions, run `untest-handle HANDLE` followed by `remove HANDLE`, including after an earlier removal. Ordinary User removal still deletes sessions. `rebuild` still deletes the session it replaces.

## Installation and deployment

Command recognition uses the first text observed for a message GUID. The pinned imsg adapter exposes no edit history: a message first observed after an offline edit to `/reset` is treated as a command. A previously received message is never reinterpreted as a command.

Run `ops/install.sh` as `chris` from the repo at `/Users/chris/git/hena-agent/ren-ai`. It creates owner-only state/log/socket directories, downloads and SHA-256-checks the pinned official V2.0.16 CLI with `ops/install-web-ui.sh` **only at install time**, and installs three per-user LaunchAgent plists **without loading them**. A differing existing plist is left untouched and causes the installer to stop for manual review. Keep the desktop logged in and awake; turn off automatic macOS installs and turn on Messages' “Send read receipts.” The server listens on `127.0.0.1:4700` (Cloudflare Tunnel for `api-msg.hena.dev`) and `127.0.0.1:4701` (Tailscale Serve HTTPS 8447). Run `tailscale serve --bg --https=8447 http://127.0.0.1:4701` on the mini; do not expose either listener directly. The operator socket is `$HOME/.local/state/ren-ai/operator/operator.sock` (owner-only directory and socket).

Create login Keychain generic-password items with `/usr/bin/security add-generic-password -U -s dev.hena.ren-ai.<name> -a api-msg -w` (enter each value at the prompt), for `turnstile`, `viewer`, `discord`, and a separate random `web-ui` password for the isolated asset process. The existing Go key is service `dev.hena.ren-ai.opencode-go`, account `personas`. The asset process uses the pinned binary at `~/.local/share/ren-ai/web-ui/bin/opencode-2.0.16` with isolated home/config/data/cache/state under `~/.local/state/ren-ai/web-ui`; it cannot read the owner's or Persona host's database or configs. It listens **only** on `127.0.0.1:47987`, which must never get a Tailscale Serve/Funnel mapping. The viewer proxies its UI assets from there, never its API. [Viewer access instructions](../../../docs/agents/persona-viewer.md).

Check the persona files in `~/git/hena-agent/persona` before starting. The approved Korean privacy copy and version `2026-09-28` live together in `packages/onboarding/src/locales/ko.json`, the **single source** for site and server. Before deploying a revision, review the complete Korean text, the unchanged service Notice, and the version there; if a future version is not approved, set it to `pending` to keep onboarding shut. The site deploys before the manually deployed API, so deploy a reviewed version on both sides before accepting its consent.

Provider facts checked September 28, 2026: [OpenCode Go's privacy table](https://opencode.ai/docs/go/#privacy) lists DeepSeek V4.1 Flash as not used for training and 0-day retention, but says its DeepSeek zero-data-retention agreement is renewed monthly and the **currently posted agreement ends September 30, 2026**. Do not assume renewal or extend that claim past its date without rechecking the primary page. [OpenCode's terms](https://opencode.ai/legal/terms-of-service) say OpenCode does not retain conversation Content but cannot control third-party model providers' retention. [DeepSeek's public policy](https://cdn.deepseek.com/policies/en-US/deepseek-privacy-policy.html) excludes downstream apps from its coverage; do not infer the actual processing country of our Go route from that policy. The public copy makes no verified-country claim. These are publication facts, not changes to the accepted provider choice.

For **first start**, sit at the Mac and add `/Users/chris/.bun/bin/bun` to Full Disk Access and Accessibility, then load the three plists with the commands printed by `install.sh`. Start the web-ui LaunchAgent before the Persona server; check `curl -sS -o /dev/null -w '%{http_code} %{content_type}\n' http://127.0.0.1:47987/` returns `200 text/html`. Approve the Automation prompts for Messages and System Events **from the launchd-started Bun** immediately. A prompt left unanswered can become a hidden denial; `tccutil reset AppleEvents` and a fresh attended start are needed to recover. Confirm Discord alerts from the running server, disk and screen checks, the V2 page at `https://chris-mini.pug-mohs.ts.net:8447/`, and a test Handle's Notice/Greeting only after privacy approval. Do not test with the maintainer's personal Conversations. There is no external offline monitor for the Korean testing period: if the Mac or server stops, Discord alerts from the server also stop.

On an **already running** mini, after this change is merged and pulled, create the separate `web-ui` Keychain item, run `packages/api-msg.hena.dev/ops/install.sh`, and review any differing existing plist instead of overwriting it. Then bootstrap **only** the new `dev.hena.ren-ai-web-ui.plist`, check its loopback page, and `launchctl kickstart -k gui/$(id -u)/dev.hena.ren-ai` to make the existing viewer serve the V2 page. Do not bootstrap an already loaded server or logs agent. No additional Tailscale mapping is required; the existing HTTPS 8447 mapping remains the only viewer entrypoint.

Deploy from another machine with `ops/deploy.sh [tailscale-ssh-host]` **after installing and loading the web-ui LaunchAgent**. It fetches and fast-forwards `main`, installs pinned dependencies and restarts web-ui then the Persona server. The daily rotation agent copy-truncates both services' stdout/stderr and keeps 14 days under the state directory. Nightly snapshots of both persona databases live only in the owner-only `backups/` directory under the state directory; snapshots older than 14 days are deleted during nightly cleanup and failures raise Discord alerts. There is no paid third-party or offsite backup for this testing period: loss of the Mac or disk loses both live data and backups. Do not remove any existing backup files or the unused Keychain backup key as part of this change. From SSH, run `/Users/chris/.bun/bin/bun run packages/api-msg.hena.dev/src/operator-entry.ts remove|block|rebuild HANDLE` or `... remove-waitlist EMAIL` with `XDG_STATE_HOME=/Users/chris/.local/state/ren-ai`. Waitlist emails have no automatic expiry; remove them on request. User removal deletes service records and the OpenCode session, not the Apple Messages history.
