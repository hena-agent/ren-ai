# Separate application, OpenCode, and Messages deployments

No script below performs the live cutover, stops existing services, changes an existing Cloudflare ingress, or edits the external OpenCode deployment. Install/restore refuse existing destinations. Run scripts with `bash`; TypeScript edges run with Bun 1.4.2 from a dependency-installed checkout. Treat exported archives as private: they contain conversations and service credentials. Encrypt and copy backups off-host yourself; no paid service is required.

## Native machine authentication adapter

Generate a **new review copy**, never edit the external source automatically:

```sh
bun packages/api-msg.hena.dev/ops/patch-opencode-proxy.ts \
  /Users/chris/git/hena-agent/oc.hena.dev/auth-proxy/server.ts \
  /absolute/private/staging/reviewed-server.ts
diff -u /Users/chris/git/hena-agent/oc.hena.dev/auth-proxy/server.ts /absolute/private/staging/reviewed-server.ts
```

The adapter matches six reviewed anchors and refuses missing, duplicated or already-patched shapes. Incoming Basic credentials go upstream unchanged, including WebSocket upgrades. A machine 401 **never** retries with the proxy's cached privileged credentials; native OpenCode validates the supplied credential. Existing cookie login still uses the cached native credential. **Initial deployment prerequisite:** at the approved proxy deployment step inspect the full diff, install the reviewed copy and rebuild only the existing proxy, without changing its internal origin networking. Through `https://oc.hena.dev`, verify valid machine Basic credentials return native API JSON, invalid credentials return401 without privileged fallback, and SSE, terminals and cookie login still work. Record this verification before any application/bootstrap start or import; do not substitute an internal HTTP URL. Tests exercise HTTP and WebSocket credential forwarding; they do not claim the live public ingress is verified.

## Persona plugin/config installation

The upstream already mounts the reserved `ren-ai-opencode-location` volume at `/srv/ren-ai:ro`. Leave that mount and every other location unchanged.

1. After completing the public-HTTPS proxy prerequisite above, inspect inherited plugins with authenticated `ops/session-transfer.ts plugins NEW-inventory.json`, setting `OPENCODE_URL=https://oc.hena.dev` and `OPENCODE_DIRECTORY=/srv/ren-ai`. Review each plugin's ID/target/source; create a JSON array of **all unrelated inherited plugin IDs/targets**, including discovered global plugin directory targets. An empty list is appropriate only when inventory proves there are none. OpenCode V2 supports `-target` removal entries, not an invented isolation setting.

   Initial inventory can be empty while a location initializes. Inspect the loaded location again before treating it as empty. On the deployed 2.0.19 instance, disabling versioned package targets did not disable the loaded plugins; their actual IDs (`henadev.anthropic-auth`, `opencode-discord-noti`, `opencode-translate`) did. Verify those plugins are absent or disabled after reloading the persona location, while ordinary locations retain them.

2. Generate config with `bun ops/location-config.ts REVIEWED-targets.json NEW-opencode.json`. Default callback is `https://api-msg.hena.dev/rpc`; override `REN_AI_CALLBACK_URL` only deliberately. The config uses the local plugin **directory** `/srv/ren-ai/plugin`, protected `/srv/ren-ai/application.token`, and compaction `buffer:400000`, `keep.tokens:12000` (1M context / 600k budget). The model remains app-selected `opencode-go/deepseek-v4.1-flash`.
3. Put `opencode.json` and `application.token` (same value as `REN_AI_APPLICATION_TOKEN`) in `REN_AI_LOCATION_INPUT`, owner-only. Start the restored application in bootstrap mode **before** booting the plugin location: its catalog/context callback is needed to initialize the plugin.
4. Validate `docker compose -f ops/compose.yml config --quiet`, then explicitly `docker compose -f ops/compose.yml --profile tools run --build --rm install-location`. The installer refuses a nonempty volume; it copies the bundle and pinned dependencies plus their generated lock, then protects config/token files. It does not mount or alter OpenCode home. For upgrades, export/review the location first; no automated overwrite is supplied.
5. Inspect the installed location's plugin inventory and agent/tool policy. Verify no unrelated inherited plugin remains, personas have only send/read/react/wait, compaction matches, ordinary OpenCode projects remain writable, and the existing native UI's features still work. A dedicated location is **not** a security sandbox.

## Standalone Messages Mac

```sh
bash ops/build-mac.sh /absolute/new/artifact /absolute/reviewed/imsg
bash /absolute/new/artifact/install.sh /absolute/new/artifact /absolute/private/imsg.env
```

Build on macOS with Bun 1.4.2 and the reviewed **native imsg0.15.9** executable, not Homebrew's shell wrapper. On the inspected host this is `/opt/homebrew/Cellar/imsg/0.15.9/libexec/imsg`; use your actual reviewed native path on other hosts. The builder takes an optional third resource-directory argument, otherwise uses the native executable's directory; it requires/copies `imsg-bridge-helper.dylib`, `PhoneNumberKit_PhoneNumberKit.bundle`, and `SQLite.swift_SQLite.bundle` beside `bin/imsg`. It rejects wrappers, wrong versions/architectures and non-system dylib dependencies. The artifact also includes Bun, gateway/probe bundles, adjacent `messages-ui.applescript`, dependency graphs and SHA-256 checksums of every payload file. It has no Homebrew/OpenCode package installation or checkout dependency. Builder and installer verify architecture/checksums; the bundle graph rejects OpenCode and unbundled output dependencies. Copying an executable preserves its signing identity; do not re-sign it casually after creating Fleet profiles.

Default stable permission identities are `/usr/local/lib/ren-ai-messaging/bin/bun` and `…/bin/imsg`, matching the Fleet tooling's `MESSAGING_HOME` contract. Use `MESSAGING_HOME` for a different **absolute** path and give the same actual paths to the MDM profile generator (`IMSG_INSTALL_ROOT` remains an installer alias). Run as the GUI user, not root; installation requests attended sudo only to create/chown its new identity directory if needed. Default GUI LaunchAgent is `~/Library/LaunchAgents/dev.hena.ren-ai-imsg.plist`; `IMSG_LAUNCH_AGENT` can change the file path. Its label remains `dev.hena.ren-ai-imsg`. Installation never bootstraps it or stops the old AI app. Only IMSG_TOKEN/PORT/LISTEN_HOST are accepted in imsg.env. Bun's environment-file loader reads that protected file without putting the token in the plist.

Complete Apple Account sign-in, Messages history sync, [Fleet enrollment/PPPC delivery and launch-context checks](mdm/README.md), desktop login/awake policy, and Messages “Send read receipts.” At the approved step explicitly bootstrap the GUI LaunchAgent. Verify the **actual launchd process**, then run the bundled no-send probe using the same token:

```sh
ROOT="${MESSAGING_HOME:-/usr/local/lib/ren-ai-messaging}"
"$ROOT/bin/bun" --env-file="$ROOT/imsg.env" "$ROOT/verify.js"
```

The probe authenticates `/rpc`, reads Messages DB and ensures/parks the UI without selecting a user or sending. After local verification, test with `IMSG_URL=https://imsg.hena.dev/rpc` from the Docker side. Unauthorized requests must fail. Messages image conversion and attachment bytes are served by the Mac; Docker never accesses its filesystem.

Provision a **separate** Mac Cloudflare Tunnel and review its dashboard route `imsg.hena.dev` → `http://127.0.0.1:4702`. Put its raw token in an owner-only file (see `messaging-tunnel.token.example`), then `bash ops/install-mac-tunnel.sh /absolute/reviewed/cloudflared /absolute/private/raw-token` installs a separate GUI LaunchAgent **without loading it**. It uses `--token-file`, never a secret command-line argument/plist value, and disables automatic binary updates. It refuses existing tunnel/plist destinations. Explicitly bootstrap `dev.hena.ren-ai-imsg-tunnel.plist` only after local verification and ingress approval. The gateway never reads that credential. The artifact includes these installer/export/restore scripts; no app checkout is needed on the replacement Mac. No script mutates the existing tunnel or starts another AI intake. Rotate Mac stdout/stderr with `bash ops/rotate-logs.sh` from your chosen daily management schedule; it keeps fourteen days.

## Initial cutover: planned pause, not two intakes

1. Keep the old app running until ready. Stage Mac artifact/MDM, Docker images and secrets. **Before starting the new application, even in bootstrap mode, apply/review the machine-Basic proxy adapter and verify valid/invalid authenticated native API access through public `https://oc.hena.dev` plus existing browser/SSE/terminal behavior.** Only then stage reviewed plugin inventory/config and proceed to the planned pause. Recheck approved Korean onboarding copy/consent version and provider privacy facts before enabling onboarding. Do not infer renewal of a historical zero-retention agreement.
2. During the approved pause, stop **old intake and scheduling**; settle work or record every pending/uncertain send. Stop its LaunchAgent and confirm no process still holds either database. Leave Apple Messages receiving. Export existing target Docker volumes as a rollback backup only during their own separately approved stop; never replace that home during the initial session import.
3. `CONFIRM_SOURCE_STOPPED=yes bash ops/snapshot-legacy.sh OLD-STATE NEW-SNAPSHOT` preserves complete application state, bookmarks/bindings/send records, plus coherent `server.sqlite` and `opencode.sqlite` copies. No original database writes. This tooling requires the original state tree, not the old GET-only viewer.
4. `bash ops/export-legacy.sh NEW-SNAPSHOT OLD-PERSONA-DIRECTORY` runs the pinned native 2.0.19 core/server **only inside a network-disabled one-off image** against a throwaway copy. It exports through native HTTP route APIs without opening a listener, invoking a restart sweep, calling the model, or loading the old plugin. Native schema migrations may update only that disposable copy. Review fidelity against stopped 2.0.16 snapshots before cutover; keep original snapshots unchanged. `sessions.json` includes all sessions in the old location (active, retained resets/removals and children) and pending user/synthetic inbox data.
5. `bash ops/install-application-state.sh NEW-SNAPSHOT/application-state` copies the separate application state into an **empty** target application volume without rewriting session IDs/bookmarks or clearing uncertain sends. Start the app with `BOOTSTRAP_ONLY=true` via `CONFIRM_STAGED_DEPLOYMENT=yes bash ops/deploy.sh`: HTTP/callback starts, onboarding is 503, tools reject execution, and no intake/scheduling/recovery/OpenCode calls run.
6. Install/verify the plugin location with the callback alive. Use `CONFIRM_BOOTSTRAP_ONLY=yes bun ops/session-transfer.ts restore NEW-SNAPSHOT/sessions.json` against the existing OpenCode. Restore checks the complete archive and all target IDs, refuses collisions/cycles/control work and fork/revert metadata, preserves IDs, imports parents first and rebinds only imported sessions to `/srv/ren-ai`. Native2.0.19 import silently omits fork/revert information; such archives require a full OpenCode home-volume restore instead of lossy API import. The legacy persona app never forked/reverted sessions. Pending user/synthetic work is queued with `resume:false`, including inline images. Existing target sessions are never overwritten. If any import fails, inspect partial target IDs before retrying; do not blindly re-run.
7. Verify session/message/tool history, retained sessions, app bindings, plugin policy, both public authenticated endpoints, native cookie/machine/UI flows, and Messages attachment/status/read/typing/reaction behavior. Reconcile physical-send uncertainty against Messages history; **never retry an uncertain send just because it is absent from imported session memory**. Pending control operations must be drained/settled before migration, not silently dropped.
8. Explicitly restart the app with `BOOTSTRAP_ONLY=false` only after verification. Recovery activates imported pending inbox work through supported APIs, intake catches up Messages history and GUID deduplication prevents replay. Verify messages received during the pause, scheduling and delivery reconciliation with a marked test Handle, not personal conversations.
9. Only after acceptance retire the old `dev.hena.ren-ai`, old log agent, viewer-only asset LaunchAgent/listeners 4700/4701/47987 and the old Tailscale8447 mapping. Do not delete snapshots or unrelated Keychain items. Old source is rollback evidence, not a second active intake. Rollback after any new physical send requires reviewing both sides' send records before resuming the old app.

## Independent future relocation

**Mac:** boot out only the messaging gateway and its separate messaging-tunnel LaunchAgents at the approved pause; `bash ops/export-mac.sh NEW-PRIVATE-BACKUP` exports both binaries, artifact, independent messaging/tunnel tokens and logs. It requires the installed tunnel so credentials cannot be accidentally omitted. On a same-architecture replacement, `bash ops/restore-mac.sh BACKUP NEW-STAGING` verifies the archive and generates both new configured-path plists **without starting**. Different architecture requires rebuilding artifact/Bun/imsg/cloudflared, then restoring only messaging/tunnel configuration/logs. Sign into the same Apple Account, synchronize history, enroll in Fleet, deliver profiles for the new actual identity paths and verify the launchd/public probe. Switch only `imsg.hena.dev` after verification. Docker services/OC credentials stay untouched; application reconciliation handles changed local Messages ROWIDs using durable GUID/date history. Confirm pause-period messages catch up.

**Docker:** at an approved pause stop all consumers of the four exported volumes, including both OpenCode upstream and cookie proxy. `OC_DEPLOYMENT_DIRECTORY=… REN_AI_TUNNEL_TOKEN=… bash ops/export-docker.sh NEW-PRIVATE-BACKUP` refuses running mounts and captures **whole home** (all locations/sessions/provider credentials/projects), proxy data (browser cookie signing identity), persona location (plugin/config/token/dependencies), and application state; it also copies the external Compose/source/env read-only, persona files, application env and separate application tunnel token. Restore supplies the latter as protected `application-tunnel.token`; read it into the Compose environment without logging it. Fleet database/certificates/secrets are exported separately by its tooling; restore them as part of a complete Docker-host move. Full-home restore preserves native fork/revert metadata and all unrelated OpenCode locations; scoped session exports are not a full-host backup.

On the new host, `bash ops/restore-docker.sh VERIFIED-BACKUP NEW-CONFIG-DIRECTORY` verifies checksums and restores into **new, nonexistent** named volumes; it never merges databases or starts containers. Default volume names match the current OpenCode project. For custom names, review a new external Compose override rather than editing/overwriting existing configuration. Review persona/env host paths, retain the verified Basic-compatible proxy, and verify the restored public HTTPS OpenCode endpoint before application/bootstrap start or import. Start the callback/application in bootstrap mode and verify plugin/catalog/session counts, native UI/cookie/Basic/SSE/terminal operation and public Mac integration before moving production traffic. Review image architecture/version and keep `https://oc.hena.dev` across hosts; use a protected staging HTTPS hostname when checking a replacement before switching the stable route. Do not invent a private HTTP/shared-filesystem or Tailscale dependency. Activate intake only once, reconcile uncertain sends and pause-period messages, then retire the old Docker host. Keep application/OC/Fleet backups and credentials together under access control.

## Verification scope

Repo tests prove the transfer and service contracts; operation tests exercise native snapshot exports, pagination, artifact graph rejection and proxy credential behavior. Validate scripts with `bash -n` and Compose with configured staging values. Image builds and private artifact/installer checks are safe before live deployment. Actual PPPC delivery, public hostname routing, old-version snapshot fidelity and native UI/model behavior require the attended staged checks above; they are not claimed complete by source tests.

After changing the plugin, build its image and run `node packages/api-msg.hena.dev/test/compiled-plugin/regression.mjs --artifact-only`. This exercises the installed bundle inside the compiled CLI using isolated fake services. It catches cross-instance schema failures that an embedded-runtime test cannot: keep the positive-number `wait` input behind its opaque Standard Schema boundary. `COMPILED_OPENCODE_IMAGE` can select the pinned CLI image when the local compatibility image is unavailable.
